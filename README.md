# MicroPython Web Lab

**日本語** | [English](README.en.md)

MicroPython Web Labは、ブラウザ内のDedicated Web WorkerでMicroPythonを実行する、非公式の開発・学習環境です。

## はじめて使うとき

保存済みコードのないブラウザでは「はじめの実験」を表示します。「実行」で内蔵LEDを点滅させ、
`interval_ms = 500`の500を200へ変えて再実行すると、コードの変更と結果を体験できます。
配線編集やデバイス一覧は「ワークスペースを開く」から利用できます。停止・エラー確認・再起動は
実験画面でも操作できます。エディタからはEscを押してからTabでフォーカスを移動できます。

次の「ボタンを試す」は、押しボタンだけを表示する簡潔な実験画面で続けられます。
上部の「実行」を押すと、初期サンプルでは8秒間、ボタンを押す・離す操作を繰り返せます。
状態が変わるたび、ボタンの入力レベルと、隣の実行結果に`Button: pressed`または
`Button: released`を表示します。実行結果欄は表示開始時から一定の高さとし、
スクロール位置は新しい出力に合わせて末尾へ追随します。
押下と解放を実行中に確認し、正常終了したら完了を案内します。
終了後も「実行」で再度試せます。LEDとボタンの実験は、それぞれ独立した実験セットです。
初めて開く際にコードと配線のコピーを作り、開き直すと編集したコピーを使います。
ボタンのセットはGP15へ配線済みです。同期入力を使えない環境では理由を表示します。
「ワークスペースを開く」で、現在のセットのデバイス、ファイル、REPLへ進めます。

同じセット内の画面切替や題材の閲覧はPythonの実行を維持します。別のセットを開くと、現在の編集を
保存してWorkerと音声を停止し、新しい初期状態を用意します。コードは自動実行しません。
従来の保存済みコードは「これまでの作業」として移行し、旧データも残します。
破損した保存データや未対応の構成は勝手に置き換えず、エラーとデータ退避の入口を表示します。
実験の案内は再読み込みで最初の段階へ戻り、編集内容は保持します。

## 主な機能

- ブラウザ上のMicroPython REPL
- 複数タブ対応コードエディタと通常実行・デバッグ実行
- Pythonのキーワード・文字列・コメントの色分け、行番号、カーソル行の強調
- デバッグ停止行の黄色い矢印と、ブレークポイントの赤い丸による位置表示
- 停止、Ctrl+Dによるリセット、Worker再生成、出力量の制限（アルファ版の実行時間は無制限）
- Pico 2 Wを対象とした機能レベルのGPIO、ADC、PWM、I2C、SPI、UARTモデル
- 仮想デバイスの配線編集とサンプルコード
- 用途別の題材選択、実験セットの作成・再開・名前変更・削除
- ファイル、編集バッファ、配線、表示状態を実験セットごとにブラウザへ保存
- 日本語・英語表示

命令単位、クロック単位、電気特性を再現する完全なMCU／電子回路シミュレーターではありません。
LEDなどの部品は、学習用途に必要な範囲で抵抗等を内蔵した機能モデルとして扱います。

アルファ版では、スクリプト・REPL・デバッグ実行の10秒自動停止を無効にしています。
長時間の処理や入力待ちを継続できます。無限ループは「停止」、またはREPL内の⌘/Ctrl+Cで
Workerを破棄して復旧してください。停止後は「再起動」で実行環境を用意します。
無限ループは手動停止までCPUを使い続けるため、実行時間の上限を設ける仕組みは内部に残します。
出力100,000文字、Pythonヒープ、ファイル容量の上限は引き続き適用します。
YM2203の予約も最大約49.7日へ拡張し、24時間などの音源側での繰り返し演奏に対応しています。
変更理由と影響は[ADR 0045](docs/adr/0045-disable-the-default-execution-deadline-for-alpha.md)を参照してください。

REPLの空の主プロンプトでCtrl+Dを押すと、Workerを再生成してPythonの変数と実行状態を初期化します。
エディタ内容と配線設定は保持します。複数行入力の空の継続プロンプトでのCtrl+Dは、その入力を実行します。
大量出力は標準出力・標準エラーの合計100,000文字で打ち切り、自動復旧します。

通常のワークスペースで画面の高さが足りない場合はページを縦にスクロールして操作できます。幅960px以上の画面では、
コード領域に約10行、REPLに約6行の最低作業高さを確保します。作業画面上部の「通常」
「エディタを広く」「REPLを広く」で表示を切り替えられ、コード、入力途中の内容、実行状態は保持します。
幅960px未満では、拡大表示中は仮想ボードも折りたたみ、通常表示で戻します。
表示の切り替えはページ内だけに適用し、再読み込み後は通常表示に戻ります。「停止」は作業画面を
スクロールしている間も上部に表示します。

## ワークスペースの画面構成

幅960px以上では、左にプロジェクトのファイルツリーとサンプル、中央にエディタ・出力／REPL、
右に実験の入口と仮想デバイスを表示します。中央と右の幅、エディタとREPLの高さはドラッグまたは矢印キーで
変更できます。幅960px未満では各領域を縦に配置します。

ファイルツリーは最初から表示し、作成・保存・名前変更・削除・ZIP入出力は「ファイル操作・ZIP」を
開いて利用します。サンプルはデバイス単体・デバイス連携の一覧や右のカードから「無題」タブで開けます。
デバイス連携サンプルの一覧は、行の間に空白を挟まず詰めて表示します。
編集中のコードは置き換えません。「ファイル操作・ZIP」から「アクティブなタブを保存」を選び、
ディレクトリとファイル名を指定して「保存」を押すと、ファイルツリーに追加し、タブ名をファイル名へ
切り替えます。保存済みファイルのタブでは同じ操作で上書き保存します。「名前を付けて保存」では
保存済みタブでも保存先を選び直せます。エディタ下部の保存ボタンも同じ動作です。
REPLの「複数行をまとめて送信」は必要なときだけ展開できます。

右の「構成・配線」で配線編集の専用ビューへ移動し、「ワークスペースへ戻る」で復帰します。
移動だけではWorkerを再生成せず、コード、入力途中のREPL、Python変数、配線編集途中の内容を
保持します。配線の適用は従来どおりWorkerを再生成します。停止・再起動は配線ビューでも利用できます。
デバイスカードは内容に合わせた高さで表示し、右ペインが広い場合は2列になります。カードを
折りたたんでもデバイスのシミュレーションは継続します。並べ替え順と折りたたみ状態はセットごとに保存し、
複数行送信欄の開閉はページ内だけで保持します。

右ペインの「題材を選ぶ」には「デバイスを試す」「ロボットと制御」「音と音楽をつくる」
「プログラミングを学ぶ」「書籍から学ぶ」の入口があります。一つの題材を複数の入口から開けます。
現在はLED、ボタン、ボタンとLEDの連携、自由なデバイス実験、YM2203を用意しています。
ロボットの物理実験と書籍連動は準備中です。
一軸アームは[物理モデル](docs/arm-physics.md)と
[MicroPythonとの同期実行基盤](docs/arm-runtime.md)まで検証しています。通常画面への接続は次段階です。「保存したセット」で続きのコードを開き、
「新しく作る」で元のひな型から別のコピーを作れます。「体験」「構成」「解説」を切り替え、
セット名の変更やデータ退避もできます。配布用の題材更新で利用者の編集は上書きしません。

通常のZIPは現在のセットの保存済みファイルを扱います。「データを退避」は、保存済みレコードと
メモリ上の下書き、旧形式データを回収するJSONです。このJSONを取り込む機能はまだありません。
ローカルDevice開発モードは従来の単一プロジェクトを使うため、通常版とは別のオリジンで利用してください。

## エディタとデバッグ

デバッグ停止中はpdbコマンド欄の`b 10`で10行目にブレークポイントを設定し、`cl 10`で解除できます。
`cl`だけで全件を解除します。ブレークポイントは実行ごとの状態で、実行終了・再起動時に消去します。

## プロジェクトファイルとZIP


「プロジェクトファイル」は`/project`以下をフォルダとファイルのツリーで表示します。
フォルダをクリックして展開・折りたたみ、ファイルをダブルクリックまたはEnterで開けます。
矢印キーで項目を移動し、左右キーでフォルダを展開・折りたたみできます。
「ファイル操作・ZIP」の「ファイルの作成」は空の「無題」タブを開きます。
ディレクトリを作るには親ディレクトリ（直下なら`/project`）を選択し、
「ディレクトリを作成」のダイアログで名前を入力します。ファイルを選択中は、そのファイルの親ディレクトリへ作成します。
ファイルやディレクトリを選択して「名前の変更」を押すと、名前だけを変更するダイアログを表示します。
「移動」では移動先ディレクトリを選び、名前を保ったまま移動します。ディレクトリの中身と開いている
タブのパスも更新します。自分自身や配下のディレクトリは移動先に選べず、同名の項目は上書きしません。
ファイルはディレクトリの行へドラッグ＆ドロップしても移動できます。`/project`の行にドロップすると
直下へ移動します。同じ階層へのドロップや、ツリーの外からのドロップは移動を実行しません。
ドラッグが使えない環境では「移動」ボタンを利用してください。
「削除」は選択項目を削除します。空でないディレクトリは、中身をまとめて削除してよいか確認します。
`/project`自体は名前変更・移動・削除できません。
保存済みファイルと内容が同じタブは、確認なしで閉じます。変更があるタブや無題タブでは、保存せずに
閉じてよいか確認します。未保存のタブ名は`●blink.py`のように先頭へ`●`を付け、ファイルの保存が
成功したら外します。保存前の内容へ戻した場合も外します。復元用の下書きを自動保存しても`●`は外しません。
タブを閉じても保存済みファイルは残ります。変更を破棄して閉じた場合は保存済みの内容を維持します。
無題タブの下書きは閉じると破棄されるため、残す場合は先にファイルとして保存してください。
「初期サンプルに戻す」はエディタを戻し、
保存済みのプロジェクトファイルを保持します。

エディタは編集後400 msで復元用の下書きを自動保存します。これはファイル本体への自動保存ではなく、
名前のあるタブと無題タブの編集内容・選択中タブをブラウザ内へ退避する機能です。ページを開き直すと
最後に退避できた内容と未保存表示を復元します。「アクティブなタブを保存」で初めてファイル本体へ
反映します。実行は編集中のコードを使いますが、importや`open()`は保存済みのファイルを使います。
無題タブはファイル名を自動生成せず、保存先を決めるまでファイルツリーやZIPには含まれません。ディレクトリの新規作成は
「ファイル操作・ZIP」のディレクトリ作成で行い、保存画面でそのディレクトリを選択します。
ファイルの上書き確認を取り消した場合や保存が失敗した場合も、無題のコードと保存画面を保持します。Pythonの
`open(..., "w")`や`open(..., "wb")`による変更、削除、移動もIndexedDBへ保存します。
ブラウザの再起動やWorkerのリセット後に復元します。保存が利用できない場合は保存状態欄に
エラーを表示します。強制停止やページの異常終了では、保存完了前の変更が失われることがあります。
同じサイトを複数ウィンドウで編集した場合は最後の保存が優先されます。

初期カレントディレクトリは`/project`、importの探索先は`/project`と`/project/lib`です。
例えば`drivers/__init__.py`と`drivers/sensor.py`を保存すると、
`from drivers.sensor import Sensor`と書けます。編集してもimport済みモジュールは自動更新されず、
再起動または空の主プロンプトでのCtrl+Dでキャッシュを初期化します。デバッグのステップ実行は
選択中ファイルが対象です。

容量は全ファイル内容で4 MiB、ファイルとディレクトリは合計1,024件、相対パスはUTF-8で
240バイトまでです。Pythonの書き込みは割り当て前に検査し、上限を超えると容量不足の
`OSError`になります。名前は大小文字を区別します。通常ファイルの書き込み先は`/project`以下です。

「ZIPをダウンロード」は保存済みのファイルのバイト内容とディレクトリを通常の無圧縮ZIPへ書き出します。
未保存の編集内容や無題の下書きは含まれません。ZIPへ含めるには先に対象タブを明示的に保存してください。
PCで展開・編集して再圧縮したZIPも取り込めます。
ZIPのルートを`/project`へ配置し、外側のフォルダがある場合は取り込み元を選択できます。
検証後に確認して全ファイルとタブを置き換え、コードは自動実行しません。配線設定と実行状態は
ZIPに含みません。取り込み失敗時は元の内容を保持します。

読み込みは無圧縮・Deflate、UTF-8指定またはASCIIの名前に対応します。暗号化・分割・ZIP64・
シンボリックリンクには対応しません。ZIP入力は8 MiB、展開後は4 MiB、エントリは1,024件、
処理時間は15秒までです。Deflate展開にはブラウザの`DecompressionStream("deflate-raw")`を使い、
未対応環境では取り込みエラーを表示します。

設計と保存形式の移行方針は[ADR 0035](docs/adr/0035-add-a-persistent-project-filesystem.md)を参照してください。

## 公開αと対応環境

このプロジェクトは公開αです。画面、機能、ブラウザ内の保存形式は変更される可能性があります。
エディタと配線設定はブラウザ内にだけ保存され、端末間の同期やサーバー側バックアップはありません。
ブラウザデータの削除や保存形式の変更に備え、大切なコードは別の場所にも保存してください。

公開αの対応対象は、Windows 11のChrome／Edgeと、Apple Silicon Mac上のmacOSの
Chrome／Firefox／Safariです。Intel Macはサポート対象外です。確認したOS・ブラウザ版と検証範囲、
IME合成・タッチ入力・GPU固有動作などの未確認事項は
[ブラウザとOSの検証](docs/browser-compatibility.md)を参照してください。

## FM＋SSG音源の試作

通常のワークスペースでも、「構成・配線」で「YM2203音源（実験用）」を接続し、
「配線を適用」してワークスペースへ戻ると音源を自動で準備します。スピーカーは初期状態でミュートです。
音源カードの「ミュート」を押して解除し、「FM／SSG発声」からコードを開いて実行してください。I2C0 / 0x44、SDA=GP8、SCL=GP9です。
接続設定とコードは通常の保存機能で保持します。再読み込み・再接続後はミュートから始まります。
切断すると音声処理も終了します。ミュートは演奏を止めず、スピーカー音量スライダーの値も変えません。
主要サンプルは「FM／SSG発声」「簡易MML」「BINプレイヤー」です。MMLで短い旋律を記述し、
BINで大きなレジスタ列を逐次転送できます。合奏・音色設定・Pocket Signalは追加例として残します。
[BIN仕様](docs/devices/ym2203-bin-format.md)、[ChatGPTへの変換プロンプト例](docs/devices/ym2203-conversion-prompt.md)、
[使い方ガイド](https://asamomiji.jp/articles/micropython-web-lab-guide/#ym2203)も参照してください。

ローカルで作成する再生テスト用のBIN、取り込み用ZIP、入力ログ、変換記録は
`local-test-data/ym2203/<test-name>/`へ保存します。このディレクトリ全体はGitの追跡対象外で、
リモートリポジトリや配布サンプルには含めません。キャッシュとは別の保存先として扱います。

音源サンプルは編集可能なPythonドライバーもプロジェクトへ追加します。音色プリセット、
MIDIノートと休符、予約演奏の指定方法は[音源ドライバーガイド](docs/devices/ym2203-driver.md)を参照してください。
「合奏サンプル」ではFM 3ch＋SSG 3chのメロディ・伴奏・ベースを一度に予約できます。
「音色設定サンプル」では、FMの4オペレーター・アルゴリズム・フィードバックと、SSGのノイズ・エンベロープをPythonから指定できます。
「音色エディター」では接続図と設定値を見ながら試聴し、編集した音色を新しいPythonタブへ書き出せます。
書き出したタブは未保存です。「保存」で保存先を選ぶとプロジェクトのファイルとZIPへ反映されます。
「試聴モード」で1.5秒の短い試聴と、停止まで継続して設定変更を反映する連続試聴を選べます。
連続試聴は閉じる操作や背景タブへの移動でも停止します。FMのエンベロープの減衰は設定どおりです。
「楽曲サンプル」では公開曲「Pocket Signal」の全曲をFM 3chで12.02秒予約演奏します。
コードの`REPEAT_MS = None`を`REPEAT_MS = 24 * 60 * 60 * 1000`へ変更すると24時間繰り返します。
予約パターンは最大131,071イベントとし、音源側で再利用するためメモリ量は演奏時間に比例して増えません。
サンプルを開く際、既知の同梱旧版ライブラリだけは更新し、実行環境を再起動します。編集版は保護します。
競合時は対象パスと「バックアップして更新」を表示します。選ぶと元のファイルと未保存の編集内容を
`ym2203-backups/`へ残して更新できます。
音色と譜面を編集でき、出典とライセンスもコード内に保持します。[移植内容と出典](docs/devices/pocket-signal.md)を参照してください。
音源カードは命令の送信・音源受付・音声処理を区別し、予約の時間・適用イベント数・完了を表示します。
音量はコードの`sound.volume(50)`（0〜100）と画面の「スピーカー音量」の両方で調整します。
強い合奏にはピークリミッターが働きます。初期試作より出力を引き上げたため、更新後は低めの設定から調整してください。

`/fm-prototype.html`に、I2Cで音色を設定して短い楽曲を予約演奏できるYM2203音源モジュールの
実現性検証ページを用意しています。「音声を有効にする」→「サンプルを実行」で、「ドレミファソファミレド」をFMだけ、続いてSSGだけで演奏します。
停止・再起動・消音、再現範囲、I2C契約と検証方法は[音源試作ガイド](docs/devices/ym2203-prototype.md)を参照してください。
このページの編集内容は永続保存されません。

## 開発環境

Node.jsとpnpmはプロジェクトで固定した版を使用します。グローバル環境を変更せず、次のコマンドで
セットアップと開発サーバー起動を行えます。

```sh
./scripts/setup-node.sh
./scripts/use-node.sh pnpm install --frozen-lockfile
./scripts/use-node.sh pnpm dev
```

ブラウザで`http://127.0.0.1:4173/`を開きます。SharedArrayBufferを使用するため、開発サーバーと
本番配信ではCOOP、COEP等のセキュリティヘッダーが必要です。

## 検証

```sh
./scripts/use-node.sh pnpm check
```

個別には、単体テスト、型検査とビルド、ブラウザテストを実行できます。

```sh
./scripts/use-node.sh pnpm test
./scripts/use-node.sh pnpm build
./scripts/use-node.sh pnpm test:e2e
./scripts/use-node.sh pnpm test:e2e:experiments
```

`test:e2e:experiments`は開発用ページと実際のIndexedDBで、実験セットの保存・移行・切替を
検証します。通常画面の入口、実Worker・音声の切替、復旧導線は`test:e2e`で検証します。
保存契約は[ADR 0051](docs/adr/0051-add-transactional-experiment-set-storage.md)、画面と移行の有効化は
[ADR 0052](docs/adr/0052-connect-experiment-sets-to-the-workspace.md)を参照してください。

製品版Chrome・Edge・Firefox・SafariとOS別の確認方法は
[ブラウザとOSの検証](docs/browser-compatibility.md)を参照してください。

## 静的配信

さくらのレンタルサーバ向けには`./scripts/use-node.sh pnpm build:sakura`で配信用成果物を生成します。
Basic認証で制限したリハーサルにも対応します。配置、HTTPS設定、公開後の検証は[配信手順](docs/deployment.md)を参照してください。

## セキュリティとプライバシー

MicroPythonコードはブラウザ内で実行し、通常の利用ではエディタ内容やREPL履歴をサーバーへ送信しません。
ユーザーコードにはDOM、任意ネットワーク、ブラウザストレージ全体を公開しない設計です。ただし、
ブラウザ内実行だけで完全なサンドボックスを保証するものではありません。

設計上の信頼境界と既知の制約は[脅威モデル](docs/threat-model.md)、脆弱性の報告方法は
[SECURITY.md](SECURITY.md)を参照してください。

現在の構成と各層の責任は[アーキテクチャ](docs/architecture.md)を参照してください。
