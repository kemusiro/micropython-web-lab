# 一軸アームの実験画面（E5）

右ペインの「題材を選ぶ」→「ロボットと制御」→「重り付き一軸アーム」から作成する。
「プログラミングを学ぶ」からも同じひな型を開ける。コード、条件、表示設定を一つの実験セットへ保存する。
ひな型の更新で利用者のコピーを変更しない。

## 最初の実験

1. 新しいセットを作る。`main.py`の制御コードと、150 g・目標60°・6秒の条件が入る。開くだけでは実行しない。
2. 共通の「スクリプトを実行」を押す。実際の制限付きMicroPythonが専用Simulation Workerを進める。
3. 「体験」でアーム、おもり、破線の目標姿勢、角度グラフを観察する。
4. 「構成」で重り、目標、初期角度、Kp、Kd、重力補償、時間を変え、再実行する。
5. 「解説」で制御API、力学、理想モデルの範囲を確認する。

構成には標準、重力補償あり、減衰を小さく、重いおもりの4条件を用意する。
プリセットは条件を変更し、コードは書き換えない。入力範囲と単位は[物理モデル](arm-physics.md)を参照する。
入力が不正なままの実行は拒否し、最後の有効値で黙って実行しない。
実行準備中・実行中は条件をロックする。系列の表示変更、題材の閲覧、体験・構成・解説の切替は計算を止めない。

アームは理想的な関節トルクで制御する。PWMや特定のモーターの電気特性は扱わない。
このセットではREPL、デバッグ、ボード配線、デバイス用のサンプル一覧を使わない。
ボードのセットへ切り替えると従来の機能へ戻る。

## 観測と時刻

SVGのアーム、数値、全グラフのカーソルは同じ確定tickを示す。
角度と目標を常に表示し、角速度、角加速度、要求・適用トルク、重力トルクを追加できる。
トルクは直前の区間[n−1,n)の保持値として階段表示する。
速度投影の起きた点の角加速度は無効と表示し、グラフを欠測点で分ける。
記録が欠けている区間も線でつながない。画面の位置差分から速度や加速度を作らない。

「計算」は最新の観測時刻、「記録を見る」は選択した過去の時刻である。
グラフを押すか時刻スライダーで選ぶ。スライダーの矢印キーは1 tick（0.01秒）、HomeとEndは端へ移動する。
「最新の観測へ」で追従へ戻る。記録の選択はPythonの実行位置や物理状態を変更しない。
探索から作業へ戻っても、同じセットなら閲覧位置と記録を保持する。

最大の行き過ぎは目標方向を考慮する。下げる実験でも向きを反転して評価し、
初期角度と目標が等しい場合は「対象外」とする。偏差は目標角度−最後の観測角度で、定常偏差と断定しない。
飽和とストッパー接触は、それぞれ該当した制御区間の数を示す。初期状態を区間数へ加えない。
指標は記録したtickに対する値で、点の間にある連続時間の真の最大値ではない。

## 描画と実行の分離

`WorkspaceRuntime`が既存のボードRuntimeとモデル実行を振り分ける。
モデルは実行ごとに最新の保存済みファイルと条件をスナップショットし、E4の新しいWorkerペアを作る。
開始時に能力を確認し、10 msの同期step、1 msのRK4、起動・通信期限をE4のまま使う。
セットを開いた時点では実行能力だけを確認し、Workerペアは実行要求で生成する。
Runtime Protocol 16、制御版1、WASM、Device APIを変更しない。

`ArmRecording`は最大1,001点の検査済み観測を表示用にコピーする。DOMや表示設定からモデルを操作しない。
通常描画は最大20回/秒、動きを抑える設定では最大4回/秒とし、表示だけを間引く。
終端、時刻選択、表示切替は即時に描画する。非表示の観察画面も記録の受信を続け、戻ったときに描画する。
未来の姿勢を推測せず、最新の確定観測を表示する。遅延が20 ms以上の場合は再生の遅れを表示する。
同条件の全数値列を通常描画と動きを抑える描画で比較し、一致することをブラウザで検証する。

停止・例外・ページ非表示ではE4の両Workerを停止し、確定した記録を残す。
再起動は再実行の準備で、過去時刻からの再開ではない。別セットへ切り替える前には停止結果の回収を待つ。
Pythonの受信済みファイルは既存の保存経路へ戻し、終了チェックポイントでは保存の完了を待つ。
未送信の変更まで強制停止で回収できるとは限らない。

## 保存と互換性

DB版2・レコード版1を維持し、次の組合せだけをモデル型として受理する。

| 項目 | 値 |
| --- | --- |
| `environment` | `{kind: "model", model: {id: "one-axis-arm", version: "1.0.0"}}` |
| `initialConditions` | `{inputs: {}, arm: …}`。armは範囲検査済みのSI条件 |
| `runPolicy` | `{kind: "fixed-step"}` |
| `view` | `{id: "arm-v1", section: …, series: …}` |
| `view.series` | `speed`、`acceleration`、`torque`、`gravity`の重複しない部分集合 |

モデルへ配線・初期デバイス入力・配線候補を混在させない。未知のモデル・版・表示・系列を拒否する。
既存のボードレコードはそのまま読める。E5以前の配布版はアームレコードを読めず、
同じDBのワークスペースが復旧表示となる場合がある。アーム作成後はE5対応版を使用する。
未知データを自動変換・削除して巻き戻さない。

ファイルと未保存バッファの区別、保存競合、容量上限、原本保護は既存の保存基盤を使う。
コード・条件を編集しても過去の結果を再計算せず、「変更前の実行結果」と表示する。
結果の条件とメタデータは開始時へ固定する。「この実行の再現条件」からハッシュや版を確認できる。
実行系列、Pythonの途中状態、閲覧tickは永続化せず、セット切替と再読込で破棄する。

## 対応範囲と検証

非分離環境・SharedArrayBuffer未対応では実行できない理由を表示し、コード・条件・解説は閲覧可能とする。
起動失敗の後も、確定済みの選択セットの作業画面へ到達できる。
日本語・英語、明暗の配色、動きを抑える設定、強制配色、幅320・736・960・1280pxを対象に確認する。
製品版Chrome・Edge・Firefox・Safari、実機モバイル、実配信先での確認は別工程である。

関連テストは`src/control/presentation.test.ts`、`src/experiments/record.test.ts`、
`src/experiments/workspace-runtime.test.ts`、`e2e/arm-workspace.spec.ts`に置く。
E3/E4の参照値、解析条件、通信期限の検証も維持する。
決定の比較は[ADR 0055](adr/0055-show-arm-experiments-in-the-workspace.md)、
Python APIと共有領域は[同期実行基盤](arm-runtime.md)を参照する。
