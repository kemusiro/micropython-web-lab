# YM2203音源のPythonドライバー

通常のワークスペースで音源カードの「サンプル」を開くと、
`lib/web_lab_ym2203_v1.py`と短い演奏コードを用意する。
ドライバーも通常のプロジェクトファイルとして保存・編集・ZIP出力できる。
これはWeb Labの独自I2Cモジュール用であり、実YM2203のI2C仕様を示すものではない。

音源は結線に合わせて準備される。スピーカーは初期ミュートなので、音源カードの「ミュート」を押して解除してから演奏コードを実行する。
既存のコードは書き換えず、新しいタブへサンプルを開く。
すでにドライバーを編集している場合は上書きせず保存状態欄で案内する。
既知の同梱旧版と完全一致するファイルは、サンプルを開く際に更新し、Workerを再起動する。
編集版や識別できない過去版は、自動更新せず競合するパスを表示する。
「バックアップして更新」を押すと、対象の保存ファイル・同名モジュールと未保存の編集内容を
`ym2203-backups/<連番>/files/`・`drafts/`へ別々に残し、サンプル用ドライバーを用意する。
開いているドライバータブもバックアップ先へ移し、再起動で古いimportキャッシュを破棄する。
「閉じる」なら何も変更しない。自分で別名保存してからサンプルを開く方法も使える。
バックアップはファイル一覧から参照・ZIP出力できる。容量不足なら更新せず元の状態を保つ。
ドライバーの通常の編集後もimportキャッシュを更新するため再起動する。

## 基本の演奏

```python
from machine import I2C, Pin
from web_lab_ym2203_v1 import YM2203

sound = YM2203(I2C(0, scl=Pin(9), sda=Pin(8)))
sound.reset()
sound.volume(50)
sound.fm_tone("soft")
sound.reserve((60, 62, 64, 65, 67, 65, 64, 62, 60), source="fm")
```

MIDIノート番号60がド（C4）、69がラ（A4、440 Hz）。`None`は休符。
`source="ssg"`へ変えるとSSGで同じ旋律を演奏する。SSGだけを比較するときは先に`reset()`してFMを消音する。
FMプリセットは`soft`（柔らかな音）、`bright`（倍音の多い音）、`bell`（ベル風）の3種類。
音色データはこのプロジェクト独自のデモ用設定で、特定の実機楽器の音質を保証するものではない。

## API v1（実験用）

| メソッド | 操作 |
| --- | --- |
| `YM2203(i2c, address=0x44)` | モジュールのプロトコル版を確認する。発音や初期化は行わない |
| `reset()` | 全音源の停止・チップ初期化・予約破棄。アンプ音量は保持 |
| `volume(percent)` | 内蔵アンプ音量0〜100。ホストのスピーカー音量とは独立 |
| `status()` | `version`、未再生登録イベント数`queued`、アンプ音量`volume`を辞書で返す |
| `fm_tone(preset="soft", channel=0)` | 選択FMチャンネルをキーオフし、音色を設定する |
| `fm_note(note, channel=0)` / `fm_off(channel=0)` | 選択FMチャンネルの即時発音・キーオフ |
| `ssg_note(note, channel=0, volume=11)` / `ssg_off(channel=0)` | 選択SSGチャンネルのトーン発音・消音。音量0〜15 |
| `reserve(notes, source="fm", channel=0, step_ms=300, gate_ms=250, tail_ms=300, ssg_volume=11, repeat_ms=None)` | 単旋律を予約。repeat_msは繰り返しの総期間。演奏期間msを返す |
| `write_register(register, value)` | YM2203レジスタを直接操作する。両引数は0〜255 |

チャンネルはFM/SSGそれぞれ0〜2。音符は整数のMIDI番号0〜127のうち、チップで表現可能な音域だけを受け付ける。
4 MHzのこのモデルではFMは0〜116、SSGは23〜127。範囲外、空の旋律、容量超過は発音命令を送る前に`ValueError`となる。

## 予約演奏

開始間隔`step_ms`、発音時間`gate_ms`、最後の余白`tail_ms`をミリ秒で指定する。
`1 <= gate_ms <= step_ms`。1周の期間は`音符・休符の数 × step_ms + tail_ms`。
演奏期間は最大4,294,967,295 ms（約49.7日）で、24時間も指定できる。
通常の1音は4イベント、休符は1イベント。合計最大131,071イベントを、I2Cの一回256バイト以内に分割する。
短い予約は従来の16ビット形式、長い予約と繰り返しは32ビット形式を使う。

```python
# この3音のパターンを音源側で24時間繰り返す。Pythonはすぐ終了する。
sound.reset()
sound.reserve((60, 64, 67), source="ssg", repeat_ms=24 * 60 * 60 * 1000)
```

`repeat_ms=None`は1回、整数指定は繰り返しの総期間とする。
総期間は1周以上、最大約49.7日。1周は100 ms以上で、`tail_ms`も1周に含む。
1周のイベントを再利用し、総期間で打ち切るため、24時間分の音符をメモリへ展開しない。
演奏中に繰り返しのための追加I2C送信は不要。新しい譜面への逐次追加を行う汎用ストリーミングAPIは未実装。

```python
# FMチャンネル2で休符を入れた旋律を予約する。
sound.reset()
sound.fm_tone("bright", channel=1)
duration = sound.reserve((60, 64, None, 67, 72), channel=1,
                         step_ms=400, gate_ms=300, tail_ms=400)
print("演奏期間:", duration)  # 2400 ms
```

モジュール全体で予約は一つ。`reserve()`は現在の予約を置き換える。
他チャンネルの発音状態は開始時に保持するが、予約期間が終わるとチップ全体を停止する。
複数チャンネルの同時予約には、下記の追加ライブラリの`reserve_score()`を使う。

Python終了後も予約は最後まで進む。Python例外、停止、再起動、配線変更、バックグラウンド移行では音声も停止する。
即時発音も最後の書き込みから最大約49.7日に延長した。FMキーオフには音色の余韻があり、
直ちに全音源を止める場合は`reset()`を使う。長時間の実演にはページを前面に保ち、
OS・ブラウザが音声処理を中断しない状態が必要。背景移動や音声処理中断では従来どおり停止する。

音源カードでは送信命令数、音源受付数、音声処理へ反映済みの数を確認できる。
予約演奏は経過時間・総時間・適用イベント数・完了を表示する。
`status()["queued"]`は未開始の登録件数で、画面に表示する再生中の残り件数とは別。
ブラウザが音声の開始・再開を保留した場合はクリック待ちを表示する。ミュート操作などで再開し、演奏を実行し直す。

連続して短い予約を演奏する例（先に音源サンプルでライブラリを追加する）:

```python
from machine import I2C
from time import sleep_ms
from web_lab_ym2203_v1 import YM2203

sound = YM2203(I2C(0))
for note in (60, 64, 67):
    sound.reset()  # 完了時はチップも初期化されるので、各回の音色を設定する
    sound.volume(30)
    sound.fm_tone("soft")
    duration = sound.reserve((note,), step_ms=500, gate_ms=400, tail_ms=100)
    sleep_ms(duration + 200)
```

各予約は最大約49.7日。Pythonの待機は音声完了の確認ではなく余裕を含む待ち時間であり、
隙間なしの長時間ストリーミングは提供しない。再生中の新しい予約は古い未適用イベントを置き換え、
チップの発音状態は維持する。音色やチャンネルを切り替える場合は先に`reset()`する。
登録キューがすでに埋まっている場合は`reserve()`を拒否する。I2C転送の途中で失敗した場合は`reset()`を試みた後、元の例外を返す。
実バスまで切断されている場合のreset成功は保証できないため、ホスト側の「停止」も利用できる。

[I2C契約と互換性の範囲](ym2203-prototype.md)、[ドライバーの設計判断](../adr/0038-add-a-project-local-sound-driver.md)。

## FM＋SSGの合奏

音源カードの「合奏サンプル」で、6chのオリジナル編曲を新しいタブへ開く。
FMのメロディ・ハーモニー・低音伴奏と、SSGの分散和音・短い拍・ベースを同時に演奏する。
従来の「サンプル」はFM／SSGの比較用として残す。
合奏サンプルでは`lib/web_lab_ym2203_score_v1.py`を追加し、既存のベースドライバーをそのまま利用する。
この追加版の`YM2203`は従来の全メソッドに加え、`reserve_score(tracks, tail_ms=300, repeat_ms=None)`を提供する。

```python
from machine import I2C
from web_lab_ym2203_score_v1 import YM2203

sound = YM2203(I2C(0))
sound.reset()
sound.volume(35)
sound.fm_tone("soft", channel=0)
duration = sound.reserve_score((
    {"source": "fm", "channel": 0, "notes": (60, 62, 64, 67)},
    {"source": "ssg", "channel": 2, "notes": (48, 55),
     "step_ms": 600, "gate_ms": 500, "ssg_volume": 9},
))
print(duration)  # 1500 ms
```

各トラックは次の辞書で指定する。

| キー | 意味・既定値 |
| --- | --- |
| `source` | 必須。`"fm"`または`"ssg"` |
| `channel` | 必須。各音源の0〜2 |
| `notes` | 必須。MIDIノート番号または休符`None`の列。空は不可 |
| `start_ms` | 共通の再生起点からの開始オフセット。既定0 |
| `step_ms` | 音符・休符の開始間隔。既定300 ms |
| `gate_ms` | 各音の発音時間。既定`min(250, step_ms)`、1〜`step_ms` |
| `ssg_volume` | SSGの各音量。既定11、0〜15 |

FM 3ch＋SSG 3ch、最大6トラック。同じ`source`・`channel`の重複と未知のキーを拒否する。
1周の期間は`max(start_ms + 音符数 × step_ms) + tail_ms`で、最大約49.7日。
`repeat_ms`を指定すると全トラックを同じ時計で総期間まで繰り返す。
イベント上限131,071件は全トラックの合計で、通常音4件・休符1件に加え各トラックの初期停止1件を含む。
同時刻では停止が発音より先で、音程レジスタの一組を分けずに並べる。
全トラックを検査してから、一つの予約として開始する。

予約を置き換えると、選択したチャンネルは時刻0でキーオフ／消音する。
開始オフセットまで直前の音を鳴らし続けない。選択外の発音状態は保持する。
FM音色も保持するため、純粋な合奏を比較する場合はサンプルのように先に`reset()`を使う。
終了時には従来どおり全チャンネルを停止する。
編集済みファイルと競合するときは二つのライブラリを自動追加・上書きしない。
設計は[ADR 0039](../adr/0039-reserve-a-multi-channel-score.md)を参照。

## FM音色・SSGノイズとエンベロープ

「音色設定サンプル」は`lib/web_lab_ym2203_tone_v1.py`と、必要なベース／合奏ライブラリを追加する。
この版も従来の即時発音・予約・合奏APIを持つ。既存の編集済みファイルは上書きしない。
FMのアルゴリズムとフィードバックの音の差、SSGのトーン＋エンベロープ、ノイズのみ、
トーン＋ノイズを順に演奏し、最後に全音源を停止する。

```python
from machine import I2C
from web_lab_ym2203_tone_v1 import YM2203

sound = YM2203(I2C(0))
sound.reset()
sound.volume(30)
sound.fm_patch((
    {"multiple": 1, "total_level": 40},  # OP1
    {"multiple": 1, "total_level": 20},  # OP2
    {"multiple": 2, "total_level": 40},  # OP3
    {"multiple": 1, "total_level": 20},  # OP4
), algorithm=4, feedback=3, channel=0)
sound.reserve((60, 64, 67), channel=0)
```

`fm_patch(operators, algorithm=4, feedback=0, channel=0)`は、四つの辞書を持つtupleまたはlistを受け取る。
アルゴリズム0〜7、フィードバック0〜7、FMチャンネル0〜2。
**辞書の順は音色図のOP1、OP2、OP3、OP4**。レジスタ番地順ではない。
選択チャンネルをキーオフしてから全設定を書き込む。未知のキー・不正な型・範囲外はI2C送信前に拒否する。
追加版の`fm_tone()`でプリセットに戻すと、カスタム音色のSSG-EG設定も解除する。

| オペレーターのキー | 範囲 | 省略時 | 意味 |
| --- | --- | --- | --- |
| `detune` | 0〜7 | 0 | DTレジスタ値。0〜3が正側、4〜7が負側（0と4はずれなし）。単位はセントではない |
| `multiple` | 0〜15 | 1 | MULT周波数倍率。0は0.5倍 |
| `total_level` | 0〜127 | 32 | TL減衰値。大きいほど小さな音 |
| `key_scale` | 0〜3 | 0 | KSキー・スケール |
| `attack` | 0〜31 | 31 | ARアタック・レート |
| `decay` | 0〜31 | 10 | DRディケイ・レート |
| `sustain_rate` | 0〜31 | 2 | SRサステイン中の減衰レート |
| `sustain_level` | 0〜15 | 4 | SLサステイン・レベルの減衰値 |
| `release` | 0〜15 | 7 | RRリリース・レート |
| `ssg_eg` | 0〜15 | 0 | FMオペレーターのSSG-EGレジスタ値。bit3が有効、下位3bitが形状 |

これらはチップのレジスタ単位であり、msや音量%ではない。`ssg_eg`はFM側の特殊エンベロープで、
以下のSSG音源の共有エンベロープとは別の設定。

| 追加SSGメソッド | 操作 |
| --- | --- |
| `ssg_noise(period)` | 共有ノイズ発生器の周期1〜31を設定 |
| `ssg_envelope(period, shape)` | 共有エンベロープの周期1〜65535と形状0〜15を設定・再トリガー |
| `ssg_mixer(channel=0, tone=True, noise=False)` | 指定SSGチャンネルのトーン／ノイズだけを変更。他チャンネルを保持 |
| `ssg_sound(note=None, channel=0, volume=11, tone=True, noise=False, envelope=False)` | 即時発音。トーン有効時はMIDI音符必須、ノイズだけなら省略可。固定音量0〜15またはエンベロープを選択 |

ノイズ発生器とエンベロープは**3chで共有**する。設定を変えると、それを使う他チャンネルにも作用する。
shapeのbit3〜0はContinue・Attack・Alternate・Hold。10は下降・上昇の繰り返し、12は上昇の繰り返し、
0は一度下降して0を保持する。shapeを書き直すたび再トリガーする。
`ssg_sound(envelope=True)`は共有位相を保持し、`volume`は固定音量時だけ作用する。
`tone`、`noise`、`envelope`はboolで指定する。ミキサーの両方をFalseにしても確実な消音にはならないため、
消音は`ssg_off()`、全停止は`reset()`を使う。

```python
# 前の予約が終わった後、SSGの波形・音量変化を試す。
sound.reset()
sound.ssg_envelope(period=5000, shape=10)
sound.ssg_sound(72, channel=0, envelope=True)
sound.ssg_noise(period=12)
sound.ssg_sound(channel=2, tone=False, noise=True, volume=9)
```

SSGの`reserve()`／`reserve_score()`は引き続き固定音量のトーン演奏用で、開始時にノイズを無効にする。
この段階ではノイズ・エンベロープの時系列予約は追加していない。
FMカスタム音色は両予約APIと併用できる。設計とレジスタの一次資料は[ADR 0040](../adr/0040-add-explicit-fm-patches-and-ssg-controls.md)を参照。

## 音色エディター

音源カードの「音色エディター」で設定画面を開く。
FMではアルゴリズム・フィードバック、OP1〜OP4の各値と接続図を表示する。
緑のOPは音の出力へ寄与し、矢印は変調先を示す。SSGへ切り替えると
トーン／ノイズ／エンベロープ、固定音量・周期・形状を指定できる。
共通のチャンネル・MIDI音符・内蔵アンプも設定する。

画面内の「ミュート」で解除し、「試聴モード」を選んで「試聴する」を押す。
スピーカー状態は「ミュート中／ミュート解除」と表示する。
ミュート状態は音源カードと共有する。ミュート中の試聴も処理されるがスピーカー出力は無音。
試聴はモジュール全体を初期化して現在の演奏を置き換える。

- 「短い試聴」は1.5秒（キーオン1秒）。設定変更は次の試聴で反映する。
- 「連続試聴」は停止するまで選択した音符を保持する。合計時間の10秒制限はない。
  設定変更は約80 msの入力待ちの後に反映して再発音する。
  FMのエンベロープは設定どおりに減衰するため、キーを保持しても一定の音量を保証しない。

連続試聴の即時発音も最大約49.7日なので、従来の2秒ごとの期限更新は不要となった。
設定を変えない間は追加I2C送信を行わず、キーオンやSSGエンベロープをやり直さない。
入力が不正な間は消音し、
有効な値へ直すと再開する。ミュートを解除するだけでは試聴を開始しない。

「試聴を停止」、閉じる、Escapeで止められる。背景タブへの移動、結線の無効化、
実行環境の停止・再起動や音声処理の中断でも連続試聴を終了し、復旧後も自動で再開しない。
実行環境が停止中の場合は画面内の「実行環境を再起動」で復旧する。
ミュート切り替えは実行環境を再起動しない。試聴できない理由は操作ボタンの下に表示する。
「初期値に戻す」は音色設定だけを戻し、「試聴を停止」は試聴を止める操作。
波形は表示幅に合わせて振幅を調整するので、見た目の大きさだけでは音量を比較できない。

「Pythonコードを見る」で生成コードを確認し、「Pythonタブに追加」で新しいタブと
必要な3ライブラリを用意する。従来のコードや編集済みライブラリは上書きしない。
競合があるときは画面内で案内する。試聴には追加ライブラリが不要なので、編集版があっても試せる。
書き出したコードは通常の保存・ZIP出力の対象となり、再読み込み後も実行できる。
書き出しは連続モードの選択にかかわらず、従来どおり短い試聴コードとする
（FMは1.5秒の予約、SSGは1秒発音してreset）。

編集中の設定案はページ内に保持し、再読み込みでは初期値へ戻る。
Pythonから変更された音色を画面へ自動反映する機能はない。
試聴は既存のMicroPython→I2C経路を使い、書き出しは音色設定APIを使う。
変換の一致と停止責務の設計は[ADR 0041](../adr/0041-add-a-host-owned-sound-patch-editor.md)を参照。
連続試聴の期限更新と変更反映は[ADR 0044](../adr/0044-add-continuous-i2c-patch-audition.md)を参照。
現在の長時間演奏・繰り返しと旧版更新は[ADR 0046](../adr/0046-support-long-native-ym2203-playback.md)を参照。

## 大容量予約の注意

音源の正式上限は131,071イベント。Pythonドライバーの`status()`は6バイトの拡張応答から
32ビット件数を返す。旧4バイト読み取りは65,535で飽和する。
既知の未編集旧ドライバーはサンプルを開いた際に更新される。編集済み版は保護され、
競合時は既存のバックアップ操作で更新できる。更新後はページを再読み込みする。

`reserve()`と`reserve_score()`のtuple/listは固定1 MiBのMicroPythonヒープも消費するため、
音源の上限より先にMemoryErrorになる場合がある。数万件以上の生レジスタデータは
ファイルから252バイトずつ読み、`05`の予約パケットへ送る方法を使う。
現行の同期JSバッファ境界のGC制約に対する暫定対策として、
同梱ドライバーは16バッチごととstatus前にPython側で`gc.collect()`を行う。
直接I2Cで大量転送するプログラムでも同じ方法を使う。
ブリッジ内GCを安全に扱えるようになれば不要となる（ADR 0048）。
1回の予約と音源側ループなら、演奏中の追加Python実行・I2C送信は不要。
累積送信予算はWorkerごとに1,024命令・425,981数値で、上限に達したら実行環境を再起動する。
詳細は[ADR 0048](../adr/0048-enlarge-native-ym2203-reservations.md)。

サンプルは新しい未保存タブで開く。ライブラリとBINはプロジェクトへ追加する。
Pythonを残すには「保存」でパスを指定する。編集済みライブラリ・同名BINの競合は更新を止める。
「バックアップして更新」はym2203-backups/へ元データを退避してから更新する。

### 簡易MML

~~~python
from machine import I2C, Pin
from web_lab_ym2203_mml_v1 import YM2203
sound = YM2203(I2C(0, scl=Pin(9), sda=Pin(8)))
sound.reset()
sound.fm_tone("soft")
sound.reserve_mml((
    {"source": "fm", "channel": 0, "mml": "t120 o4 l4 c d e f g f e d c2"},
    {"source": "ssg", "channel": 0, "mml": "o3 l2 c f g c", "ssg_volume": 8},
))
~~~

reserve_mml(tracks, tempo=120, tail_ms=300, repeat_ms=None)は総期間msを返す。
全トラックは0 ms開始、sourceはfmまたはssg、channelは0〜2で重複不可。
mmlは必須、source=fm、channel=0、ssg_volume=11が既定。FM音色は先に設定する。
全MMLを検証し、キューが空の場合に予約する。

| 記法 | 意味 |
| --- | --- |
| c d e f g a b | 音符。大小文字を区別しない |
| r | 休符 |
| c+, c#, b- | 半音上げ・下げ |
| o4 | オクターブ0〜9。C4＝MIDI 60 |
| >, < | オクターブを1上げる・下げる |
| l4 | 既定の長さ。分母1〜64 |
| c8, c4. | 個別の長さ・付点1個 |
| t120 | 四分音符毎分32〜400。トラック内の変更可 |
| q7 | 音符長の7/8を発音。1〜8 |

既定o4・l4・q7。空白を許可。ループ記法・タイ・和音記法・音色番号・コメントは未対応。
和音は別チャンネルへ分ける。未知の記法を黙って省略しない。
各トラック8192文字・1024音符／休符、全体4096レジスタイベントまで。
PMD/MUCOM等との互換性は示さない。大きな曲は[BINとWYM1仕様](ym2203-bin-format.md)を使う。
[ChatGPTへの変換プロンプト例](ym2203-conversion-prompt.md)も参照する。
