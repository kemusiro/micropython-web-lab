# YM2203 FM＋SSG I2C音源モジュール試作

この試作はYamaha等の公式製品ではない。YM2203の通常の音色・発音レジスタを、独自I2Cモジュールとして操作する。
実チップのI2C仕様を示すものではない。

## 起動と操作

通常ワークスペースでは配線編集の「YM2203音源（実験用）」を接続し、「配線を適用」する。
結線に合わせて音声処理を準備し、スピーカーはミュートで開始する。
音源カードの「ミュート」を押して解除し、「サンプル」から新しいエディタタブを開いて実行する。
通常画面のサンプルは[Pythonドライバー](ym2203-driver.md)で旋律と音色を指定する。
ライブラリ`lib/web_lab_ym2203_v1.py`もプロジェクトに追加し、保存・編集できる。
「合奏サンプル」は6ch同時予約用、「音色設定サンプル」はFMの各設定とSSGノイズ・エンベロープ用の追加ライブラリを用意する。
接続設定とコードは既存の保存機能を利用する。既定では未接続で、保存済み配線へ自動追加しない。
再読み込み・再接続後はミュート。切断時は予約を破棄し、AudioContextを終了する。
ミュートと音量スライダーは独立しており、ミュート中も準備済みの音源では演奏処理が進む。
ブラウザが開始を保留する場合はクリック待ちを表示し、ミュート操作などの利用者操作で開始する。
音源準備未完了・未対応・読込失敗は画面へ表示し、発音命令を受け付けない。
設計は[ADR 0043](../adr/0043-couple-audio-to-connections-and-separate-speaker-mute.md)を参照。
停止・再起動・配線変更・Python例外では音声も停止する。統合の設計は[ADR 0037](../adr/0037-integrate-an-opt-in-sound-module.md)を参照。

専用ページで試す場合:

```sh
./scripts/use-node.sh pnpm dev
```

`http://127.0.0.1:4173/fm-prototype.html`を開く。「音声を有効にする」をクリックし、
「サンプルを実行」を押す。「ドレミファソファミレド」（C4–D4–E4–F4–G4–F4–E4–D4–C4）を、
FMだけ、続いてSSGだけで演奏する。各音250 ms、音の開始間隔300 msで、同じ高さとテンポを比較できる。
各パートは36イベント・3秒の予約演奏。FMの終了後にチップを初期化し、余韻がSSGと重ならないようにする。
出力欄には演奏する音源名を表示する。SSG予約開始後、Pythonは500 msだけ待ち、音源はPython完了後も最後まで再生する。

予約中にも「停止」「消音」を使用できる。「停止」はWorkerを破棄し、
「再起動」で復旧する。編集内容は保持するが、このページは永続保存を行わない。
ページ離脱・別タブへの移動でも停止する。演奏を再開するには再起動して実行する。
スピーカー音量と消音はホスト側の操作であり、I2Cのアンプ設定とは独立する。
音源出力には固定4倍の増幅を適用する。I2Cアンプ値とスピーカー音量は、それぞれ0〜100%の倍率として作用する。
高出力の合奏ではピークリミッターが働くため、アンプ設定を上げても比例して大きくなるとは限らない。
初期試作の過度な減衰を修正したため、保存済みサンプルも以前より大きな音で鳴る。

## I2C契約 v1

I2C0、SDA=GP8、SCL=GP9、7-bitアドレス`0x44`。一回の転送は最大256バイト。
バスの転送時間・電気波形は再現せず、I2C受付成功は音声処理の完了を意味しない。

| 操作 | ペイロード | 意味 |
| --- | --- | --- |
| `writeto_mem(0x44, reg, bytes((value,)))` | 1バイトのみ | YM2203レジスタを即時書き込み |
| `writeto` | `00 reg value [reg value …]` | レジスタの順序付き一括書き込み |
| `writeto` | `01 ms_lo ms_hi reg value […]` | 絶対時刻付きイベントを予約に追加 |
| `writeto` | `02 duration_lo duration_hi` | 予約を開始し、登録キューを空にする |
| `writeto` | `03` | 発音停止、チップ初期化、予約破棄。アンプ音量は維持 |
| `writeto` | `04 percent` | 内蔵アンプ音量0〜100（初期値50） |
| `readfrom(0x44, 4)` | 応答4バイト | 版1、登録キュー件数low/high（65,535で飽和）、アンプ音量 |
| `readfrom(0x44, 6)` | 応答6バイト | 版1、件数byte0/byte1、アンプ音量、件数byte2/byte3。正確なuint32件数 |
| `writeto` | `05 ms0 ms1 ms2 ms3 reg value […]` | 32ビット絶対時刻付きイベントの追加 |
| `writeto` | `06 duration0 duration1 duration2 duration3 [loop0 loop1 loop2 loop3]` | 長時間予約の開始。任意のloopは1周の期間 |

`readfrom`の件数はI2Cモデル内の**まだplayされていない**登録件数。
再生中イベント数・音声処理完了・BUSYを示すものではない。6バイト以降は0。
旧4バイト読み取りでは65,535を超える件数を65,535へ飽和させ、0への折り返しを防ぐ。
6バイト読み取りでは `byte1 | byte2<<8 | byte4<<16 | byte5<<24` で正確な件数を得る。
`readfrom_mem`によるチップレジスタ読み返しは非対応。

時刻と期間はlittle-endianのミリ秒。予約イベントは時刻が後退しない順に登録する。
同時刻の命令は登録順に実行する。最大131,071件、期間は1〜4,294,967,295 ms（約49.7日）、
最後のイベントは期間以内でなければならない。無効なパケットは状態を変更せず拒否する。
一回の予約パケットは16ビット形式で最大63イベント、32ビット形式で最大42イベント。
両形式を合わせ、同じ順序・容量の検査を行う。既存の`01`・`02`は最大65,535 msで使える。
`06`のloopを指定すると同じイベント列を再利用し、総演奏期間まで繰り返す。
1周は100 ms以上、全イベントは1周以内、総演奏期間は1周以上とする。
1周が終わってもチップをresetせず、絶対サンプル位置で次の周へ進む。最後は総期間で消音する。
24時間分のイベントを展開せず、保存パターンは131,071件までとする。
新しいplayは発音状態を維持しながら再生中の予約を置き換える。音色初期化が必要な場合は先に`03`を送る。
即時writeは予約中にも使え、予約の終了期限を維持する。予約がない即時制御にも
最後のwriteから最大約49.7日の期限を適用する。停止、キーオフ、resetを明示して使う。
予約期間を変える場合は新しい期間でplayし直す。時刻拡張の設計は[ADR 0046](../adr/0046-support-long-native-ym2203-playback.md)を参照。

大容量予約の容量・移行・送信予算は[ADR 0048](../adr/0048-enlarge-native-ym2203-reservations.md)を参照。
全曲を一度に予約する場合、Pythonにはイベントを大量のtupleで保持せず、
32ビット時刻＋reg＋valueのバイナリを最大42件ずつ読んで`05`へ送ると固定ヒープを節約できる。

通常画面では送信、AudioWorkletの受付、音声処理で反映された命令数を表示する。
予約の経過時間・総時間・適用イベント数・残り件数は音声処理から取得する。
配送中、予約演奏中、即時制御中、演奏完了、停止を区別する。
PLAYINGは音声処理が進行中の意味で、消音・無音の音色でも表示される。
音声処理への反映はOSや実スピーカーへの出力完了を保証しない。
停止・音声処理の再生成ごとに古い応答を除外する。設計は[ADR 0042](../adr/0042-confirm-audio-delivery-and-playback.md)を参照。

## 音源と再現範囲

- ymfmコミット`81aec25ccbb98f4873a255f7551ac4dadac59b4a`、4 MHz、FM3ch（4オペレーター）、SSG3ch。
- OPN_FIDELITY_MIN、固定2 MiB WASM、出力レートへの面積平均による再標本化、DC除去、モノラル混合。
- 出力段は固定4倍×I2Cアンプ値。瞬時アタック・50 msリリースのリミッターで振幅0.95以内に制限し、その後にホスト音量を適用する。
  チップの音色やFM／SSGの相対音量は変更しない。実アンプ特性の再現ではない。
- FMアルゴリズム、倍率、エンベロープ、SSGトーン／ノイズ／エンベロープは上流音源で処理する。
- Timer A/B、BUSY、IRQ、CSM、SSG外部I/Oポート、実DAC・アンプ特性、完全な波形一致は検証対象外。
- 波形はホスト音量適用後の出力を表示振幅の自動調整で描画する。FM／SSGメーターは混合前の合成音を表示する。
- HTTPS／localhost、AudioWorklet必須。未対応・音源読込失敗は画面へ表示する。
- 音の操作遅延にはMessagePort・OS・音声出力機器の遅延が含まれる。
  画面の出力遅延は`AudioContext.baseLatency`の目安で、操作からスピーカーまでの実測値ではない。

上流: [ymfm](https://github.com/aaronsgiles/ymfm)、[音源実装](https://github.com/aaronsgiles/ymfm/blob/81aec25ccbb98f4873a255f7551ac4dadac59b4a/src/ymfm_opn.h)。
ブラウザ構成: [AudioWorklet＋WASM](https://developer.chrome.com/blog/audio-worklet-design-pattern/)。

## 再ビルドと検証

生成済みWASMは管理対象とし、直接編集しない。Emscripten 6.0.6の`emcc`／`em++`を用意して実行する。
グローバルNodeを置き換えないため、Emscriptenの子プロセスもプロジェクトNodeを使う。

```sh
./scripts/use-node.sh ./scripts/build-ymfm.sh
./scripts/use-node.sh pnpm test
./scripts/use-node.sh pnpm build
./scripts/use-node.sh pnpm exec playwright test e2e/fm-prototype.spec.ts e2e/fm-module.spec.ts
```

Pythonドライバーの正本は`src/drivers/web_lab_ym2203_v1.py`。
`src/drivers/ym2203.test.ts`は固定MicroPythonでこのソースを実行し、I2Cモデルと固定音源のPCMまで検証する。

ビルドスクリプトは上流アーカイブとLICENSEのSHA-256、Emscripten版を検査する。
上流変更は行わず、`runtime/ymfm/wrapper.cpp`で呼び出しと再標本化を実装する。
出力は`src/vendor/ymfm-build/ym2203.wasm`、ハッシュは`runtime/ymfm/artifacts.sha256`。
初回はGitHubの公開ソースをダウンロードするためネットワークアクセスが必要。

Clangは上流のOPL専用rhythm分岐に配列境界警告を出す。OPNの`rhythm_enable()`は常に0なので
YM2203ではこの分岐に入らない。上流ファイルへ修正や警告抑制を加えていない。

音声経路・上限・停止の設計は[ADR 0036](../adr/0049-prototype-i2c-fm-audio.md)を参照。

検証済み範囲：固定WASMのFM/SSG/混合PCMと音色差、44.1/48 kHz、予約のサンプル境界、
長時間の期限と停止、繰り返し境界、I2C不正入力／容量上限を単体テストする。ブラウザ検証結果は作業時点の記録として
別途報告し、未実施のブラウザ・実スピーカー・聴感評価を検証済みとは扱わない。
