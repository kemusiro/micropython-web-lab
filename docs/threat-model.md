# 脅威モデル

## 対象と前提

この文書は、ブラウザで利用者が入力したMicroPythonコードを実行するWeb Labを対象とする。
入力コード、保存された下書き、配線設定は信頼しない。静的ファイルを配信するWeb
サーバーは任意コードを実行せず、MicroPythonはDedicated Worker内のWebAssemblyとして動く。
未発表コンテンツは通常ビルドと公開候補ツリーへ含めない。将来オプションコンテンツを公開する場合も、
外部入力として形式検証し、利用者の明示操作なしに実行しない。

保護する対象は、同一オリジンのDOM、Cookieや認証情報、ブラウザストレージ、ネットワーク到達性、
利用者のコードと設定、および画面を操作できる可用性である。ビルドに混入する改変から配布物を守る
ことも対象に含める。

## 信頼境界

```text
untrusted Python / saved draft / connection project
                  │
                  ▼
        restricted MicroPython WASM
                  │ allowlisted machine API only
                  ▼
        virtual-device model in Worker
                  │ versioned messages + allowlisted input channels
                  ▼
             browser main thread
                  │
                  ▼
                DOM / storage
```

WorkerはDOMを直接持たないが、それだけをセキュリティ境界とはみなさない。MicroPythonから
JavaScriptへ到達できればWorkerの`fetch`や`postMessage`を利用できるため、WASMビルドから汎用の
`js`と`jsffi`を除外する。JavaScript側から登録するモジュールは許可リスト方式とし、M11.2では
Device Hostで検証されたGPIO、ADC、I2C、SPI、UART、PWMだけを持つ`machine`を登録する。M12では
上限付きコマンドを同期受信して停止・再開状態を通知する`_web_lab_debugger`も登録する。このブリッジは
デバッグ実行中だけコマンドを受け付け、DOM、ストレージ、ネットワークを公開しない。M16で追加した
グローバル変数スナップショットは件数と各文字列長を制限し、プロトコル検証後にテキストとして表示する。

## 想定する脅威と対策

| 脅威 | 現在の対策 | 残る制約 |
| --- | --- | --- |
| PythonからDOM、Worker API、任意JavaScriptへ到達する | `js`、`jsffi`、JS hookをビルド時に無効化し、直接インポートを回帰テストする | MicroPythonまたはEmscripten自体の未知の脆弱性は排除できない |
| Pythonから外部ネットワークへ通信する | `socket`、`network`を公開せず、インポート失敗を回帰テストする | 将来追加するデバイスAPIに通信機能を含めない設計審査が必要 |
| 非公開コンテンツが通常ビルドへ混入する | 通常ビルドの参照をno-op境界へ固定し、明示的な公開許可リストからクリーンツリーを生成して禁止文字列と管理版バンドルを検査する | 将来公開するオプションコンテンツには形式検証、出典、完全性確認の設計が別途必要 |
| 無限ループで画面全体が停止する | Dedicated Workerをメインスレッドから破棄し再生成する | 実行中のREPL状態と仮想デバイス状態は失われる |
| 無限実行や大量出力で資源を消費する | 1実行10秒、標準出力・標準エラー合計100,000文字でWorkerを破棄して自動再生成し、Worker側でも同じ出力上限を適用して超過通知後の転送を止め、端末描画をフレーム単位に集約する。Pythonヒープを1 MiBに固定する | メインスレッド自体の脆弱性、再起動頻度、WASM全体のメモリ監視は未整備 |
| 改変された上流ソースやツールでビルドされる | リリースタグ、コミット、アーカイブSHA-256、Emscripten版を固定し、生成物SHA-256を記録する | ビルドコンテナと署名付きリリースは未整備 |
| 不正なWorkerメッセージでUI状態を壊す | 型と版を持つプロトコルをメインスレッドで検証する。Device Model状態は平坦なスカラー値、16 KiB、正の順序番号に制限する | 同一ページへ侵入済みのJavaScriptに対する防御ではない |
| デバイスUI宣言から任意コードやDOMを挿入する | 管理版で許可した固定種類と上限付きピクセル表示だけを既知フィールドで検証し、固定DOMを生成する。文字列は`textContent`、RGB332は最大16,384ピクセルの固定Canvasへだけ描画し、宣言へHTML、CSS、JavaScript、イベント、Canvas APIを含めない | 高帯域表示や第三者向け描画を追加する場合は別途脅威評価が必要 |
| 不正な接続グラフで別デバイス、未対応ピン、競合資源へ接続する | スキーマ版、Board Profile、Device ID・版、全ポート、種別、GPIO、バス、I2Cアドレス、SPI CSをDevice Model生成前に検証する。管理版は固定グラフだけをビルドし、UIを読み取り専用にする | 編集・インポート・永続化を追加する前に、未解決Device版とデータ移行を含む入力境界の再評価が必要 |
| ローカル複数構成が任意コード、意図しないpath、競合配線を読み込む | Local Device Configurationではpath sourceだけを許可し、realpath、entrypoint境界、期待Device ID・版、全source適合、合成グラフを起動前に検査する。loopbackだけで配信し、通常buildへの構成非混入を検査する | Node importとWorker実行はサンドボックスではなく、信頼できるローカルコードだけを対象とする |
| 不正な`device.json`で能力や読み込み先を偽装する | 未知フィールド、版、ID、相対JavaScript entrypoint、7ポート種別、I2Cアドレス、重複ID、64 KiB上限をSDK検証器で確認し、検証後のコピーをfreezeする | SPDX識別子の許可方針と成果物ハッシュ検証は公開前に追加する |
| 共有メモリからDOMや秘密情報へ到達する | 名前・値域・版・容量を持つ許可済み入力だけをレイアウトへ登録し、指紋と長さを検証する。PythonとDevice Modelへバッファを公開しない | Worker自体が侵害された場合、入力値の改変は防げない |
| デバッガ待機で時間制限を回避する、または共有コマンドを破損する | デバッガコマンドを4,096 UTF-8バイトに制限し、format marker、version、状態、長さを検証する。待機時間だけを除外し、再開前後の実動時間と出力量を累積する。停止と`quit`はメインスレッドからWorkerを破棄できる | 利用者コードは自身のデバッグ実行を意図的に待機させられるが、メインスレッドや他の実行主体はブロックしない |
| ブラウザ保存された配線で未宣言ポート、競合資源、過大データを注入する | 保存を64 KiB、64デバイス、1デバイス32ポートに制限し、未知フィールド、Board Profile、Device ID・版、全ポート、ポート種別、GPIO占有、I2Cアドレス、SPI CS、UART peerをメインスレッドとWorkerで検証する。不正データは実行せず管理版へフォールバックする | 同一オリジンの利用者は自身の保存データを変更できるが、任意JavaScriptや外部Deviceコードには変換しない |
| UART共有入力やGPS周期NMEA生成でメモリを消費する、またはデータを黙って失う | 1キュー4,096バイト、1転送256バイト、共有入力とDevice Modelの合計4,096バイトに制限する。GPSは単調増加時計を同期境界だけで評価し、1 Hzの最新GGA/RMCだけを保持して、飛ばした周期と置換を状態へ記録する | 入力頻度の制限は未実装。未読スナップショットは履歴として保持されない |
| 第三者Device Modelが時間機能を悪用して非決定的・高負荷になる | 公開時計は0以上で後退しないミリ秒値だけを返し、日時、タイマー登録、コールバック、DOM、ネットワークを公開しない。適合テストには手動時計を提供する | モデル自身が行う過剰な同期計算は、Worker全体の実行時間制限とレビューに依存する |
| 高周波PWMを波形イベントとして通知しUIやWorkerを過負荷にする | PWM Device APIは設定変更時の正規化信号だけを同期通知する。RGB LED状態は平坦なスカラー値と1バイトRGB332に限定し、周期ごとの波形やタイマーを生成しない | 短時間に大量の`duty_u16()`変更を行うコードは全体の実行時間制限に依存する |
| I2C転送で過大なメモリ消費や情報流出を起こす | Bus 0、7-bitアドレス`0x50`、最大256バイトに制限し、状態通知へ転送データ本体を含めない | 将来追加するデバイスごとに状態容量と公開範囲の再評価が必要 |
| 外部スクリプト、iframe、ブラウザ機能を悪用する | 既定拒否CSP、クロスオリジン分離、Permissions Policy、MIME sniffing防止を配信時に適用する | CSP違反レポートの収集と本番Nginxの継続監視は未整備 |

## 公開前に必要な追加対策

- Nginx設定例を実際のVPSへ適用し、公開URLのHTTPS応答とセキュリティヘッダーを検証する。
- Worker再起動頻度とWASM全体のメモリ使用量に上限を設け、長時間運用時の可用性を試験する。
- 依存物と生成物のライセンス、脆弱性、更新手順を定期的に確認する。
- 認証、課金、クラウド保存を追加する場合は、MicroPython実行オリジンとの分離を改めて設計する。
- 新しい仮想デバイスは、DOM、ストレージ、認証情報、汎用ネットワークを渡さない狭いAPIとして
  個別に脅威評価する。

## 公開Device APIで追加する境界

Device API v1は現在Draftであり、未承認の第三者コードを管理版で動的に実行する許可を与えない。
管理版はGitHub Pull Requestでソース、依存、ライセンス、適合テストをレビューし、Managed Catalogへ
固定したデバイスだけを静的ビルドする。任意URL、パッケージ名、Gitリポジトリをブラウザから指定して
管理版オリジンへ読み込む機能は提供しない。

Device ModelにはDOM、ネットワーク、ストレージ、汎用JavaScriptブリッジをAPIとして渡さない。ただし、
TypeScriptの型と依存注入だけではJavaScriptのWorkerグローバルに対する完全な隔離にならない。初版の
管理版は固定ソースのレビューと禁止API検査を前提とし、未承認コードの安全な動的実行を保証しない。

M11.1のBoard Profileは、存在しないピン、未対応バス、初版と異なるピン割り当て、資源競合を
Device Model生成前に拒否する。これは設定の完全性を高める境界であり、JavaScriptコードを隔離する
セキュリティサンドボックスではない。保存形式の既知の旧IDだけを正規Profileへ変換し、任意のProfile名や
外部定義を動的に解決しない。

初版のI2CとSPIは1回256バイト、UARTは1回256バイトかつ受信待ち4,096バイト、Device Stateは16 KiBを
上限とする。転送データ本体を状態通知へ自動複製せず、SPI応答長、UARTキュー容量、PWMの有限値と値域を
ホスト側で検証する。UART入力やPWM更新を利用して状態更新を大量発生させるデバイスも、出力量制限と
Worker再生成の対象とする。

ローカル開発モードは開発者自身のコードを試験する場所とし、画面へ未承認であることを表示する。第三者が
配布するセルフホスト版は管理版と異なる出典とビルド種別を表示する。未承認コードを管理版で実行する将来
機能には、別Workerまたは別オリジン、同期デバイスAPIの通信方式、署名、リソース制限を含む新しい脅威
評価が必要である。詳細な初版契約は`docs/device-api-v1.md`を正とする。

M11.4のローカル検査はパッケージのライフサイクルスクリプトを実行せず、禁止語の静的検査をimport前に
行う。ただし適合検査そのものはビルド済みDeviceDefinitionをNode.jsへimportするため、隔離境界ではない。
難読化や間接参照を含む悪意あるコードの安全性を保証せず、開発者が信頼できるローカルコードだけを対象とする。
通常の管理版ビルドはローカル仮想モジュールを空に解決し、ローカルパスとコードを含めない。

M11.2は公開へ向けてDevice APIの値域と資源上限を実装する段階であり、悪意あるコードに対する完全な
サンドボックスの証明ではない。公開判断は上記の配信対策と残る資源制限を実装し、第三者デバイスの
適合テストとブラウザ統合テストを通した後に行う。
