# ADR 0042: 音源命令の配送確認と再生状態

- 状態: Experimental
- 日付: 2026-10-11
- オーディオ有効化・ミュート操作は[ADR 0043](0043-couple-audio-to-connections-and-separate-speaker-mute.md)で更新。以下は当時の決定。
- 予約時間・即時制御の期限と累積イベント数は[ADR 0046](0046-support-long-native-ym2203-playback.md)で更新。

## 背景と選択肢

I2C受付成功は音声処理の完了ではなく、従来のメーターだけでは命令が配送待ちか不明だった。
ホストは任意のメーターで未確認命令数を0へ戻していたため、古い応答でも新しい命令を確認済みにしてしまう。
停止直後に演奏すると、停止前のメーターが新しい試聴の終了表示を上書きする可能性もある。
I2C読み取りへ音声状態を同期する案は、WorkerとAudioWorkletの異なる時計・同期読み取り契約を変える。
今回はホストとAudioWorkletの内部配送だけを明確にし、I2Cは既存の受付契約を維持する。

## 決定

公開I2Cコマンド、Runtime Protocol 15、Device SDK、保存データ、Pythonライブラリは変更しない。
ホスト→AudioWorkletの内部コマンドをversion 1、停止世代、連番を持つenvelopeで送る。
音声処理は順序を検査し、適用直後に受付応答を返す。次のrender後のメーターは
最後に適用した命令番号、再生モード、状態、経過／総時間、総／適用／残りイベント数を返す。
受付はイベント予約の登録までであり、全イベントの実行完了ではない。
画面は送信数・受付数・音声処理へ反映した数と、配送中・再生中・完了・停止を区別する。
メーターは10 Hz、命令の受付は累積番号で確認し、未受付命令の上限256を維持する。

停止ごとにホストが世代を進め、出力Gainを即座に0へする。新しい世代の最初はstopにする。
旧世代、未送信番号、後退する番号・フレームの応答を排除する。
現在の送信番号より古いメーターは累積確認に使えても、再生表示には使わない。
音声処理の再生成も新しい世代で開始する。内部プロトコルは一緒にビルド・配信し、外部互換APIとしない。

自然終了ではチップ・フィルター・リミッターを初期化し、最後の進捗を完了として残す。
明示停止は予約と進捗を破棄し、停止として表示する。
新しい予約は古い未適用イベントと期限を置き換え、発音状態は従来通り維持する。
予約中の即時レジスタwriteは期限を延長しない。予約がない即時制御は最後のwriteから8秒に制限する。
旧試作の期限延長へ依存していた場合は新しい期間で予約し直す。

AudioContextが一時停止すると出力を遮断し、再有効化を案内する。再開時には予約を破棄し、明示的な再演奏を必要とする。
PLAYINGは処理が進行中の意味で、実際の可聴音・OS出力完了を保証しない。
8秒を超える予約、隙間なしのストリーミング、I2Cによる音声完了確認はこの変更に含めない。

## 検証

DOMなしで世代・順序・累積確認・不正応答を検証する。
固定音源コアで44.1/48 kHzの予約置き換え、期限維持、反復再生のPCM一致・完了後の無音を確認する。
ブラウザで連続予約、置き換え、進捗・受付表示、停止・再起動・一時停止からの再演奏を確認し、
従来の音色編集・合奏・停止・過剰命令テストを再実行する。
