# ADR 0034: 初回はLEDの実験に集中できる画面を表示する

## 状態

採用

## 背景

エディタ、REPL、配線編集、全デバイス、サンプルを同時に表示すると、初めて使う人が
次の操作と結果を見る場所を選びにくい。コードの実行と編集による変化を小さな実験で体験させたい。

## 決定

- 保存済みコードのないブラウザは「はじめの実験」を既定とし、内蔵LEDの点滅コードを表示する。
- 実験画面では既存エディタ、実行ボタン、簡潔な内蔵LED表示、実行結果だけを中心に表示する。
  配線編集、デバイス一覧、REPL、デバッグ、詳細な保存操作は通常ワークスペースで利用する。
- 両画面で同じエディタとRuntimeClientを維持する。表示切り替えではWorkerを再生成せず、
  コード、Python変数、REPL入力途中の内容、配線、ペイン比率を保持する。
- 実験のLED表示は既存のGPIO状態通知から投影する。UIが点滅を演出したり配線を変更したりしない。
- 成功した実行中にLEDの点灯とその後の消灯を確認してから編集の案内へ進む。
  編集後の成功した点滅で次の作例への入口を示す。エラー、停止、無関係なコードでは完了にしない。
- 完了判定に端末文字列を使わない。RuntimeClientが識別子とWorker世代を確認した実行結果を利用し、
  再起動・停止時には進行中の実験を取り消す。
- 選択した画面のみを`micropython-web-lab:app-screen:v1`へ文字列`experiment`または`workspace`として保存する。
  既存のエディタ・配線の保存形式は変えない。設定なしの既存プロジェクトとローカルDevice開発は
  通常ワークスペースを既定とし、不正な保存データのエラーも通常画面に残す。
- 案内の進行はページ内の状態とし、再読み込みで最初の案内へ戻る。復元した編集内容は保持する。
  通常画面から実験を開く際は既存の実験タブを再利用し、なければ別タブを用意する。
- 実験中の停止、起動失敗時の再起動、エラー出力を簡単な画面から操作できるようにする。
  実験の出力プレビューは末尾4,000文字に制限し、全出力は既存端末の上限内に保持する。

## 結果

初回の操作と観察対象を絞り、実行後の編集へつなげられる。依存パッケージ、Worker通信、
シミュレーションモデル、セキュリティ境界、コード・配線の保存形式は変更しない。
表示設定を保存できなくても画面の切り替えと停止・復旧は利用できる。
