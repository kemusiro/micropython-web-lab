# ADR 0054: モデル用MicroPythonをSimulation Workerへ同期接続する

- 状態: Accepted（E4の実行基盤。通常画面への接続はE5）
- 日付: 2026-10-19
- 前提: [一軸物理モデル](../arm-physics.md)、[ADR 0053](0053-add-a-deterministic-one-axis-arm-model.md)

## 決定と選択肢

制限付きの既存WASMを変更せず、専用のMicroPython WorkerとSimulation Workerを一実行ずつ生成する。
Pythonは許可した`weblab.control`から同期読取とstepを行い、モデルはE3の固定刻みを維持する。

Pythonの同期APIを通常のpostMessageだけで実装すると、WASMの呼出しを中断・再開する追加機構が必要になる。
今回は版付き共有領域とAtomicsの要求・完了番号で一周期を受け渡す。同一Workerでの協調yieldは代替案とし、
実証で共有方式が成立したため採用しない。UIタイマーで物理状態を先へ進める代替経路も設けない。

Runtime Protocolを15から16へ更新する。`start.runtimeProfile`に`kind: arm`、制御版1、条件、実行ID、
共有領域を渡し、`ready.capabilities`の`arm-control-v1`を確認する。モデルとボード配線・共有デバイス入力・
デバッガの混在は拒否する。不明なモデルや版でPicoを生成しない。ボード側の既存起動経路は維持する。
旧Workerと新クライアントの組合せは不一致として拒否し、両者を同じ配布物で更新・再読込する。
保存レコード、WASM成果物、Device APIは変更しない。

## 実行と停止

メインスレッドの`ArmRuntimeSession.start`は両Workerの準備だけを行い、コードは`execute`で明示的に開始する。
起動は10秒、各stepの完了待ちは1秒を期限とする。Atomics.waitはWorker内だけで使う。
実行中の条件変更は受け付けず、再実行では新しい実行ID・共有領域・Workerを使う。

Simulation Workerは一要求につき10 msを計算し、仮想時刻に応じて待機する。遅れがあってもtickを飛ばさず、
遅延msを通知する。`time.sleep_ms`や`ticks_ms`は実時間のまま、仮想時刻はstepだけで進む。
通常のボード・REPLの無制限ポリシーは変更しない。

停止、例外、通信障害、出力量制限、Workerエラー、ページ非表示では共有中止フラグで待機を解除し、
メインスレッドから両Workerを破棄する。相手の終了応答を破棄の前提にしない。`step`を呼ばない無限ループも同じ方法で停止する。
モデル型では自動的な単独Workerの再生成やREPL・デバッグを許可しない。新しいペアでの再実行を要求する。

## 観測と再現条件

共有領域は固定96,168バイト。1,001行×12列のFloat64に、整数ヘッダーと要求トルクを持つ。
モデルだけが観測を書き、行を完成してから整数tickをAtomicsで公開する。公開済みの行を変更しない。
通常通知は50 ms以上間隔を空け、ホストは最大128点・16 KiB以内のフレームをコピーして返す。
終了時は最大1,001点・128 KiB以内の全確定記録を一度回収する。停止時も確定済みの接頭部分を保持する。

セットID、世代、実行ID、モデル・積分器版、単調増加sequence、tick、有限値、配列長、フラグを検査する。
加速度のnullは有効性ビットと数値0で表し、無効な0を測定値として扱わない。制御通知を標準出力へ混在させない。
実行バッファと開始時の全プロジェクトにSHA-256を付け、条件、Runtime参照、通信版、積分刻みを結果へコピーする。
Pythonのファイル更新もメインスレッドで保持し、結果へ返す。新しい永続保存への接続はE5で行う。

## Pythonとホストの境界

モデル型だけに`weblab.control.Experiment`を提供する。私有ホストモジュールは一つの操作ディスパッチに限定し、
プリミティブの入力とJSON文字列だけを受け渡す。共有メモリ、Worker、DOM、ストレージ、任意ネットワークを渡さない。
トルクも数値JSONで渡し、WASMブリッジの整数表現による切詰めを避ける。有限性と上限は別々に扱う。

固定版JsProxyの属性検索はプロトタイプもたどるため、新しいモジュールと関数はnullプロトタイプでfreezeする。
固定ブリッジが使うcallアダプターも同様に制限し、FunctionやObjectのコンストラクターへの経路を作らない。
ホスト例外は上限付きのエラーJSONからPythonのRuntimeErrorへ変換する。
ハンドルは一実行につき一つで、終了後、未知の関節、非有限トルク、長さを超えるstepを拒否する。

## 検証と残る範囲

実WASMから参照4ケースを実行し、全601観測をE3と比較する。通信相手の破棄、期限切れ、stepの有無が異なる
無限ループ、非分離環境、ページ非表示、再実行、原本とは独立したファイルと実行メタデータを検査する。
単体では旧能力、古い世代・完了番号、起動期限、不正メッセージ、ハンドル寿命、テレメトリ上限を検査する。

E4は開発用fixtureで接続を確認する段階である。通常のロボット入口は準備中を維持する。
E5で保存・カタログ・2Dアーム・グラフへ接続する。製品版ブラウザ間と実機の検証は残る。
詳細は[実行基盤仕様](../arm-runtime.md)を参照する。
