# ADR 0033: REPLのリセット要求と大量出力から復旧する

- 状態: Accepted
- 日付: 2026-10-04

## 背景

固定WASMの`replProcessChar()`は、空の主プロンプトでCtrl+Dを受けると非ゼロの終了要求を返す。
従来はこの戻り値を無視し、Pythonの変数が残っていた。複数行入力の空の継続プロンプトでのCtrl+Dではゼロを返して
入力を実行するため、キーの値だけでリセットを判断できない。

また、非行バッファ方式のWASMコールバックはバイト単位で発生する。その都度Workerメッセージを送り、
端末全体を描画すると、メインスレッドの出力量制限が処理される前に通知が滞留した。

## 決定

- REPLの非ゼロの戻り値を`repl-reset`制御イベントとしてメインスレッドへ通知する。
  その入力の残りを旧インタープリターへ渡さず、Workerを破棄・再生成する。
- WASM内部だけのソフトリセットは実装しない。既存の再生成経路を使うことで、Pythonと仮想デバイスの
  初期化を同じライフサイクルで扱う。Python変数、インポート状態、Worker内ファイル等は保持しない。
  エディタ、配線、共有入力領域はメインスレッドに保持する。押しボタンは既存の再起動と同じく解除する。
  ADC等の入力値は次のデバイス読み取りでモデルと表示に同期される。
- 出力はストリーム順を保ってWorker内で集約する。改行、4,096文字、ストリーム切り替え、制御通知、
  入力処理の終了で転送する。改行で同期的に転送し、出力直後にGPIOを待つコードでも表示を届ける。
- Workerは1入力メッセージまたは1スクリプトで合計100,000文字を超えたら、残りを破棄して
  `output-limit`を一度通知する。メインスレッドがWorkerを破棄するまで、追加出力を転送しない。
  Worker内タイマーや非同期メッセージの処理を待たず、同期WASMの出力コールバックで制限する。
- Ctrl+Dで複数行入力を実行する場合も、改行と同じくメインスレッドの実行時間監視を開始する。
  Workerが実際に各改行・Ctrl+Dを処理する直前に`repl-executing`を通知して監視を開始し直す。
  先行入力のプロンプトが遅れて到着し、次の実行の監視を解除してしまう競合を防ぐ。
- ADR 0011のメインスレッド側制限も維持する。Worker側の制限は通知キューの飽和を防ぐ追加対策であり、
  無限実行の強制停止は引き続きメインスレッドが担当する。
- 端末モデルへ順に書き込み、全文の切り詰めとDOM描画はアニメーションフレーム単位に集約する。

## 影響と移行

通信版を12から13へ更新する。UIとWorkerは同じビルドで配信し、旧ページは再読み込みする。
保存データ形式、Device API、固定WASMと上流生成物は変更しない。

固定WASMを使う単体テストで、主プロンプトのリセットと複数行入力の完了を区別する。
ブラウザテストでは変数消去、エディタとADC値の保持、LED初期化、4種類の無限出力からの復旧と再実行を確認する。
出力文字数は既存クライアントと同じJavaScriptの文字列長（UTF-16コード単位）で数える。
