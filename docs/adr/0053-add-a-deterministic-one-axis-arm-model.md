# ADR 0053: 固定刻みの一軸アーム物理モデルを独立して実装する

- 状態: Accepted（E3の数値モデル。画面・Python接続は後続）
- 日付: 2026-10-19
- 前提: [実験セットの基盤](../experiment-set-foundation.md)

## 背景

コードで関節トルクを指定し、重り、重力、摩擦、トルク飽和による動きの違いを観察したい。
画面の描画やWorker通信と同時に導入すると、数値の違いが物理式・積分・通信のどこから来るかを
切り分けにくい。E3は数値モデルと参照制御器に限定し、既存画面で実験可能とは表示しない。

## 決定と選択肢

`src/physics`へDOM、時計、ストレージ、ボード、MicroPythonに依存しない実装を置く。
一様な棒と先端の点質量を鉛直面内の一自由度として扱い、関節トルクを直接入力する。
モーターの電気特性、歯車、バックラッシュ、静止摩擦、接触力、実機の損傷判定は含めない。

10 msの制御区間でトルクを保持し、1 msの古典的RK4で積分する。整数tickを時刻の正本とする。
比較用の0.5 msでも制御周期を変えない。単純なEuler法は実装が短いが、同じ刻みでの誤差が大きくなりやすい。
外部物理エンジンは多剛体には有用だが、一軸の検証には依存・設定・版管理の負担が増える。
初版では独自の短い実装を解析解、エネルギー収支、刻み幅比較で検査する。

トルク飽和とストッパーをモデル側で適用し、要求値と実際の値を区別する。各内部刻みの後で角度を
可動域へ投影し、外向き速度だけを0にする。境界に静止し外向きの力が働く状態は拘束として保持する。
衝突時刻の厳密な探索や反発係数は扱わない。

## データの境界

`OneAxisArm`は一つの有限長の計算を管理し、`step`一回で一制御区間だけ進む。
開始のtick 0を含め最大1,001観測と1,000区間を保持する。読取・記録・結果の返却はコピーとする。
完了、途中停止、計算中を区別し、停止後・上限後の進行を拒否する。
全内部刻みと出力の検査を終えてから状態を確定するため、不正なトルクや非有限値で部分進行しない。

観測とトルク区間を別配列にし、tick nで決定したトルクは[n,n+1)に作用する。
角加速度は力学式から計算する。境界で静止中の拘束加速度は0とし、拘束を除いた加速度も区別する。
速度投影のあった区間の終端では通常加速度を`null`とする。衝撃による速度の不連続を有限な加速度や
衝撃力へ置き換えない。将来の数値メッセージへは有効性フラグを含めて変換する必要がある。

参照制御器`runArmControl`はSI単位と範囲を検査し、標準のPD制御と任意の理想重力補償を実行する。
`OneAxisArm`の物理定数の変更と0.5 ms刻みは数値検証用で、初期の実験画面へは公開しない。
実行条件・物理パラメータ・モデル版・積分器版を結果へコピーする。E3のTypeScript型は内部契約で、
保存形式やPython公開APIではない。実行ID、ソース・依存ファイルのハッシュ、世代、通信期限はE4で接続する。

## 検証と制約

棒の慣性、水平角の符号、平衡トルク、等加速度・粘性減衰の解析解、摩擦なしのエネルギー、
摩擦・ストッパーによるエネルギー減少、外力の仕事、飽和、境界からの離脱を検査する。
合意済みの4参照ケースと刻み幅半減を照合し、NodeとChromiumの数値列を許容差付きで比較する。
同じ実装・同じ条件での再実行は同じ列となるが、全ブラウザのバイト一致や実機との一致は保証しない。

実験セット保存、Worker通信、Device API、権限、本番依存、既存のボード・音源機能は変更しない。
物理モデルは通常画面のバンドルから未参照で、準備中の表示を維持する。E4で同期実行を実証し、
E5でアームと時系列表示を接続する。詳細と参照値は[一軸アームの物理モデル](../arm-physics.md)を参照する。
