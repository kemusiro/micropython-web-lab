# ADR 0005: machine.Pinの背後に独立した仮想GPIOモデルを置く

- 状態: Accepted
- 日付: 2026-08-26

## 背景

初期の内蔵LED作例は`machine.Pin`でLEDを操作する。WebAssembly版には実機用の
`machine`モジュールがないため、Web Lab側で機能レベルの代替実装が必要である。将来はボタン、
ADC、PWM、I2C、SPI、UARTなどへ拡張するが、UIとシミュレーション状態を直接結び付けると、
自動テスト、複数表示、デバイス追加が難しくなる。

公式WASMラッパーは`registerJsModule`でJavaScriptオブジェクトをMicroPythonモジュールとして
登録できる。検証の結果、Pythonから`Pin(...)`を呼ぶ際はJavaScriptの呼び出し可能オブジェクトが
`new`なしで実行されるため、JavaScriptクラスをそのまま公開できないことも確認した。

## 決定

仮想GPIOの状態モデル、MicroPython APIアダプター、UI表示を次の三層へ分離する。

1. 仮想GPIOモデルはピンID、モード、値、順序番号を管理し、DOMとMicroPythonへ依存しない。
2. `machine`モジュールアダプターは関数ファクトリー`Pin`を公開し、モデルの操作へ変換する。
3. UIはWorkerから受け取った状態のコピーだけを表示し、モデルのオブジェクトを共有しない。

Workerからの`device-state`メッセージには、種類、単調増加する順序番号、ピンID、モード、値を
含める。プロトコルバージョンを3へ更新し、メインスレッドで値を検証する。古い順序番号は
表示へ適用しない。

M3では`Pin.IN`、`Pin.OUT`、`value()`、`on()`、`off()`、`toggle()`、`init()`だけを提供する。
入力ピンへの書き込みはエラーとする。プル抵抗の引数は互換性のため受け取るが、動作は実装しない。

## 結果

- 仮想GPIOの状態遷移をブラウザUIなしで単体テストできる。
- MicroPython APIと表示方法を、状態モデルとは別々に変更できる。
- Worker再生成によって仮想ボードも確実に初期化される。
- 内蔵LED作例が必要とする出力ピン操作の基盤ができる。
- M3は機能レベルのシミュレーションであり、実機の電気特性やタイミングを再現しない。
- 外部コンテンツの取り込みは行わず、仮想GPIOモデル自体を独立して検証する。
