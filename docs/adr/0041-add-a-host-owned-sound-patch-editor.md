# ADR 0041: ホスト所有の音色編集・試聴画面

- 状態: Experimental
- 日付: 2026-10-11
- オーディオ有効化・ミュート操作は[ADR 0043](0043-couple-audio-to-connections-and-separate-speaker-mute.md)で更新。以下は当時の決定。
- 連続試聴と編集中の自動反映は[ADR 0044](0044-add-continuous-i2c-patch-audition.md)で追加。

## 背景と選択肢

音色設定APIを、4オペレーターの接続図とパラメーターを見ながら試したい。
UIからAudioWorkletへ直接発音命令を送れば試聴できるが、I2Cで制御するモジュールの検証経路を通らない。
保存ライブラリを試聴のために自動更新すると、編集版と競合する。

## 決定

音源カードからホスト所有のモーダルを開く。FMの全設定、8種類の接続図、SSGのノイズ・エンベロープ、
チャンネル・MIDI音符・内蔵アンプを編集し、同じ音声グラフの出力波形を表示する。
設定案はDOM表示・MicroPython状態と分離した型付きデータとしてUIに保持する。
公開Device UI／Device APIに専用コンポーネントや音声権限を追加しない。

試聴は整数・boolと音域を検査し、レジスタ設定・予約を行う固定形式のPythonを生成する。
既存RuntimeClientで実行し、machine.I2C→デバイスモデル→AudioWorkletを通す。
プロジェクトファイル・編集中のソースを変更せず、追加ライブラリも使わない。
試聴は一回1,500 ms（発音1,000 ms）、モジュール全体をresetしてから選択チャンネルだけを鳴らす。
SSGのノイズ／エンベロープも、既存のレジスタ予約を内部で使う。公開予約APIの拡張は行わない。
実行環境がreadyでないと試聴しない。REPL・ファイル操作中も待つ。
実行環境が停止・エラー状態なら音声有効化時に再起動する。モーダル内にも再起動ボタンを用意し、
音声だけが有効でも試聴できない理由を表示する。設定初期化や音声停止を実行環境の復旧と混同しない。

変更は次の試聴に反映する。変更・停止・閉じる・Escapeで自分の試聴だけを止める。
命令配送前に停止する場合はWorkerも停止し、配送済みならホスト出力と予約を遮断する。
既存の実行エラー・再起動・切断・背景移行による停止責務も維持する。
画面を開くだけでは、ユーザーの既存の演奏を止めない。

「Pythonタブに追加」は同じ設定から追加ドライバーのAPIを使うコードを生成する。
既存の3ライブラリの競合・容量検査を行い、新しいタブと必要なファイルを用意する。
失敗時はモーダル内で案内し、既存ソースとライブラリを保持する。
API単位とレジスタへの変換が一致することを、固定MicroPython・WASMのPCM比較で検証する。

編集案はページ内だけで保持する。書き出したPythonは通常の保存・ZIP出力を利用する。
別の設定保存形式・新規依存・汎用コード実行権限・ネットワーク機能を追加しない。
Pythonからの音色変更をエディターへ自動反映する機能やチップレジスタ読み戻しは含めない。

## 検証と一次資料

設定範囲、独立したOPデータ、生成コードの有効性、各チャンネルで試聴と書き出しの
レジスタ／PCM一致を単体テストする。ブラウザでFM・SSG、コード保持、書き出し・再実行・復元、
入力エラー、編集済みドライバーの保持、閉じる／停止／Escapeを確認する。
PC・モバイル幅で入力・スクロール・操作ボタンを確認する。
接続図は素材を複製せず、次の一次資料の接続関係をSVGで描く。
