# ADR 0035: 永続化するプロジェクトファイルシステムを提供する

- 状態: Accepted
- 日付: 2026-10-10

## 背景

エディタタブはソース文字列を保持していたが、MicroPythonのimportが読むファイルとは
対応していなかった。複数ファイルのプログラムと、Pythonが生成するデータをブラウザ内に
保存し、普通のZIPを介してPC上の編集と往復できるようにする。

## 決定

- `/project`を初期カレントディレクトリとし、利用者の永続ファイル領域にする。
  エディタタブはこの領域内の相対パスを持つ。Pythonのchdirはエディタの保存先を変えない。
- 総ファイル内容は4 MiB（4,194,304バイト）、ファイルとディレクトリは合計1,024件、
  相対パスはUTF-8で240バイトを上限とする。4 MiBはWeb Labの利用可能容量であり、
  ファームウェア領域や実機のファイルシステム管理領域を再現する値ではない。
- Emscripten MEMFSのノード作成、書き込み、サイズ変更、削除、移動を外部ラッパーで
  検査する。サイズ増加は割り当て前に拒否し、PythonにはENOSPCを返す。開かれたまま
  削除されたファイルも、閉じるまでは容量・件数に数える。シンボリックリンクとmmapは
  提供しない。通常ファイルへの書き込みと名前空間の変更は`/project`以下に限定する。
- importの探索先は`/project`と`/project/lib`とし、組み込み・登録モジュールを維持する。
  通常の`sys.modules`キャッシュを維持し、編集後の確実な再読み込みはWorkerのリセットで行う。
  デバッグは選択中ファイルの行を対象にし、import先のステップ実行は初期範囲に含めない。
  Pythonが削除・移動したファイルの旧パスのタブは閉じ、後の保存で旧ファイルを再作成しない。
- ファイルとエディタの正本はメインスレッドに保持し、IndexedDBの一つのトランザクションで
  保存する。Worker起動時に復元する。既存localStorageのエディタ保存は初回に取り込み、
  ページを離れる直前の未確定エディタ変更には小さなlocalStorageの退避記録も使う。
- Workerから版・単調増加revisionを持つスナップショットを送る。通常通知は100 ms以上
  間隔を空け、SharedArrayBufferの確認フラグで未確認通知を一つに制限する。実行終了時は
  最終チェックポイントを送信する。保存側は処理中一件と最新の待機一件に集約する。
  プロトコルを14へ更新し、旧Workerの応答と不正なファイルデータを拒否する。
  REPLの完了は入力IDを持つ制御通知で判断し、出力文字列で実行監視を解除しない。
  REPL実行中もエディタ・ファイル操作をロックする。復元用下書きの退避はファイルへ同期しない。
- SharedArrayBufferが使えない場合は、実行中通知を一操作につき一件に制限し、通常終了時に
  最終状態を退避する。強制停止で残る状態は、メインスレッドが受け取った最後の状態になる。
- 通常終了・REPLリセットの最終チェックポイントはIndexedDBの確定を待つ。強制停止や
  ページの異常終了では、ブラウザ保存が完了した状態までの復元を保証する。

## ZIP

- `/project`の内容をZIPのルートに置き、UTF-8名、無圧縮、通常ZIPとして書き出す。
  バイト内容・改行・空ディレクトリを維持し、アプリ独自のmanifestを必須にしない。
  保存済みのファイルスナップショットから生成し、未保存のエディタ下書きは含めない。
  テキストエリアで表示するだけでは改行を変更せず、実際の編集時にエディタの改行を保存する。
- 無圧縮とDeflateを読み込む。入力は8 MiB、ZIPエントリは1,024件、処理時間は15秒まで。
  別Workerで展開し、実際の出力も4 MiB以内かを逐次検査する。暗号化、分割、ZIP64、
  特殊ファイル、曖昧な非ASCIIの旧文字コード名には対応しない。
- 絶対パス、ドライブ文字、逆スラッシュ、親への移動、制御文字、重複パス、
  ファイルとディレクトリの衝突、重なるデータ範囲、ヘッダー不一致を拒否する。
  展開サイズとCRC32を検証してから、利用者の確認を経て領域全体を置き換える。
  失敗時は元の保存内容を維持し、取り込んだコードを自動実行しない。
- 取り込み前にディレクトリ構造を表示し、外側のフォルダを除きたい場合は、利用者が
  取り込み元ディレクトリを選択する。大小文字は区別し、隠しファイルも通常の内容として保持する。
- ファイルシステムのバイト内容が対象であり、実行中変数、importキャッシュ、デバイス状態、
  配線設定、OSのファイル権限・時刻はZIPに含めない。

## 実行環境

反復書き込みの検証で、固定ヒープのGCが`emscripten_scan_registers`を呼び出した際に
中断することが判明した。上流のstandard variantと同じAsyncifyビルド設定を有効にする。
上流api.jsへの小さなパッチで`runPythonAwaitable`を追加し、コード・結果のバッファを
非同期ccall完了まで保持する。REPLは上流の`replProcessCharWithAsyncify`で直列処理する。
Pythonヒープ1 MiB、WASMメモリの自動拡張禁止、JS・ネットワーク遮断は維持する。
ソース版とEmscripten版は変更せず、ビルドスクリプトからパッチを再適用し、生成物ハッシュを更新する。

## 制約と移行

2026-10-11の画面試作では、自動保存を復元用下書きのバックアップとして扱う。既存の`filesystem`と
`tabs`を分けて使い、保存形式は維持する。明示的な保存だけがエディタの内容をファイルへ反映する。
実行は編集中のバッファを直接使い、importとopenは保存済みファイルを使う。新しい終了時の退避記録も
下書きだけを復元する。初回の旧形式取り込みは従来のファイル名割り当てを維持し、すでに自動保存で
書き込まれた既存ファイルの内容は巻き戻さない。

ブラウザ保存には利用可能なIndexedDBが必要で、失敗は保存状態欄で通知する。保存完了前の
変更は障害時に失われる可能性がある。別ウィンドウの同時編集は最終保存が優先される。
既存の接続設定・UI設定の保存キーは維持し、旧エディタ保存も上書きせず読み込めるようにする。
今後のファイル形式変更は保存レコードの版を更新し、移行処理を追加する。
