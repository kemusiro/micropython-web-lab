# ADR 0019: Device UIを許可リスト方式の宣言から描画する

- 状態: Accepted
- 日付: 2026-08-30

## 背景

M3からM10までの仮想LED、ボタン、ADC、I2C表示は、`index.html`と`main.ts`にデバイス固有のDOM、
要素ID、イベント処理を直接実装していた。この方式では管理版へデバイスを追加するたびにWeb Lab本体を
変更する必要があり、第三者デバイスへUIを開放すると任意HTML、CSS、JavaScriptを実行させる危険がある。

Device API v1は、Device ModelをDOMやUIフレームワークから独立させ、平坦な状態スナップショットと
型付き`DeviceAction`だけを境界にする。MicroPythonの同期実行中はWorkerのイベントループが処理できない
ため、ボタン、ADC、UART入力にはM11.2の共有入力経路も維持する必要がある。

## 決定

Device UI v1は、版、タイトル、説明、固定部品列だけを持つ宣言として検証する。初版で許可する部品は
状態テキスト、デジタルインジケーター、モーメンタリボタン、数値スライダー、最大256文字の短い
テキスト入力に限定する。未知の部品、未知のフィールド、重複ID、不正な値域を拒否する。UIを必要としない
デバイスは空の部品列を使用できる。

DOMはメインスレッドの共通レンダラーが標準要素と固定CSSだけで生成し、宣言の文字列は`textContent`へ
設定する。宣言へ任意HTML、CSS、JavaScript、DOM ID、イベント処理を指定する機能は設けない。
DOMイベントから取り出したプリミティブ値は宣言に照らして検証し、`DeviceAction`へ変換した後だけ
共有単一値または上限付きUARTキューへ渡す。DOMイベント自体をWorkerやDevice Modelへ渡さない。

Workerプロトコルをv9へ更新し、`device-model-state`でインスタンスID、デバイス単位の順序番号、平坦な
状態スナップショットを通知する。Device Hostとメインスレッドの両方で値種別と16 KiB上限を検証する。
レンダラーは状態から別の表示ビューを生成し、古い順序番号を無視する。状態キー不足や型不一致は該当部品の
表示エラーとし、他のデバイス表示を停止しない。

既存のLED、ボタン、ADC、I2C固有DOMを削除し、SPI、UART、PWMを含む7リファレンスデバイスを同じ宣言型
レンダラーへ移行する。既存のPythonサンプル、回帰検証、同期入力の値域と動作は維持する。

## 結果

- Device Model、表示ビュー、DOM状態を別オブジェクトとして管理できる。
- 管理版は承認済みの宣言だけを固定部品へ描画でき、デバイス宣言から任意コードを実行しない。
- 新しいデバイスカードはWeb Lab本体へデバイス固有DOMを追加せず構成できる。
- ボタンはポインターとキーボードで操作でき、ラベル、標準フォーム部品、状態通知を共通化できる。
- `SharedArrayBuffer`がない環境では入力部品を無効にして理由を表示し、出力状態の観測は継続する。
- 専用グラフィックや高速な連続描画は初版の対象外であり、追加時に描画境界と脅威を再評価する必要がある。
