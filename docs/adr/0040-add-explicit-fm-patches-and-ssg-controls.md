# ADR 0040: FM音色とSSGノイズ・エンベロープの設定API

- 状態: Experimental
- 日付: 2026-10-11

## 背景と選択肢

プリセットとレジスタ直接操作だけでは、4オペレーターの音色を編集・比較しにくい。
既存のベース／合奏ライブラリを更新する方法は、保存済みの編集版と競合する。
追加ライブラリ`web_lab_ym2203_tone_v1.py`を合奏版のサブクラスとして提供し、
既存の両ライブラリは変更しない。音色編集画面を作る前に、明示的な設定APIを用意する。

## 決定

`fm_patch(operators, algorithm=4, feedback=0, channel=0)`は四つの辞書を受け取り、
OP1〜OP4の順からレジスタのオフセット0、8、4、12へ変換する。
各オペレーターのDT、MULT、TL、KS、AR、DR、SR、SL、RR、SSG-EGを扱う。
OPNA向けのLFO／AM設定は含めない。全設定を検査してから、選択チャンネルのキーオフと
完全な音色設定を一回の61バイトI2C転送へまとめる。未知のキー・不正な型・範囲外は送信前に拒否する。
追加版の`fm_tone()`は従来のプリセットを設定した後、カスタム音色のSSG-EGをクリアする。

`ssg_noise()`と`ssg_envelope()`は共有発生器の設定で、後者のshape書き込みは再トリガーを行う。
`ssg_mixer()`と`ssg_sound()`は選択チャンネルだけのトーン／ノイズ設定を変更する。
ミキサーの他チャンネルと上位I/Oビットを保持するが、I/Oポート自体の動作は従来どおり対象外。
`ssg_sound()`は固定音量または共有エンベロープを選択でき、ノイズだけなら音程を省略できる。
エンベロープを使うチャンネルを増やしても位相を再トリガーしない。

予約APIは引き続きSSGの固定音量トーン用とする。既存のミキサー・予約動作を変更せず、
ノイズ・エンベロープの時系列予約は別の拡張として扱う。FMのカスタム音色は既存予約と併用できる。
I2C契約v1、Runtime Protocol 15、Device API v1、保存形式、音声経路・停止責務を維持する。

## 配布と検証

音源カードの「音色設定サンプル」で3ライブラリをプロジェクトのコピーに準備し、新しいタブへ開く。
いずれかに競合・容量超過があれば一つも追加せず、編集済みファイルは上書きしない。
サンプルはFMの接続・フィードバック変更と、SSGのトーン＋エンベロープ、ノイズ、トーン＋ノイズを順に試す。
実行完了時はresetで音を止める。新しい依存や外部素材は追加しない。

固定MicroPython→I2Cモデル→固定WASMのテストでビット配置、3chのOP順、音色差、SSG波形、
不正入力の無送信、合奏APIとの併用、プリセット復帰、ファイル保護を検証する。
ブラウザではサンプルの発音、停止、import、保存・再読み込み、編集版の保持を確認する。
