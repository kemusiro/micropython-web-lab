# ADR 0046: 32ビット時刻と音源側ループで長時間演奏を扱う

- 状態: Experimental
- 容量とstatusの拡張は[ADR 0048](0048-enlarge-native-ym2203-reservations.md)で後継。以下の1,024件は当時の上限。
- 日付: 2026-10-12
- 識別できない過去版・編集版の明示的な復旧は[ADR 0047](0047-back-up-conflicting-sound-libraries.md)で追加。

## 背景と選択肢

利用者は8秒の試作用予約枠を外し、24時間などを演奏期間として扱いたい。
16ビットミリ秒の既存I2C形式では65.535秒までしか表せない。
時間とイベント容量は独立した制限であり、PCMを演奏期間分メモリへ蓄える必要はない。

32ビット時刻へ拡張する案、全音符を長期間分展開する案、Pythonで予約を繰り返す案、
音源側でパターンを再利用する案を比較した。32ビット時刻と音源側ループを採用する。
実質的な長時間枠として最大4,294,967,295 ms（約49.7日）を提供し、24時間を含める。
最大1,024イベントのパターンを再利用するため、容量と転送量は総期間に比例して増えない。

## I2C、Pythonと音声処理

既存の`00`〜`04`と4バイトのstatus（版1）を維持する。`01`・`02`は16ビットの全範囲で使える。
`05`は時刻uint32 little-endian＋reg＋valueの6バイトイベントを追加し、1パケット最大42件とする。
`06`は4バイトの総期間でplayする。続けて4バイトの1周期間を送ると繰り返す。
1周は100 ms以上、総期間以下、全イベントは1周以内とする。
極端に短い周期での命令集中を避け、イベント容量を増やしてCPU負荷を無制限にしない。
全入力はDevice Model・Runtime Protocol・AudioWorkletの境界で検証する。

内部のplay命令へ任意の`loopMs`を追加する。既存命令とフィールドは同じ意味を保つ。
公開Device SDK、Runtime Protocolの版、保存形式、固定音源コアと依存は変更しない。
新しい命令は新しい配布版の拡張であり、古い版へ渡すと拒否されるため画面を再読み込みする。

`reserve()`と`reserve_score()`は任意の`repeat_ms`を受け取る。
省略／Noneは1回、整数指定は繰り返しの総期間。1周にはtailを含む。
短い通常予約は既存のパケットを使用し、長期間・繰り返しでは32ビット命令を使用する。
入力・容量・期間を送信前に検証し、転送失敗時には部分予約を破棄する。

AudioWorkletは既存イベント配列を保持し、1周ごとにカーソルだけを戻す。
各イベントは`開始frame + round((周番号 × 1周ms + イベントms) × 出力rate / 1000)`へ変換する。
毎周丸めた長さを足し続けないため、44.1 kHz等でも丸め誤差を累積しない。
周の境界ではチップ・エンベロープ・出力フィルターを初期化せず、同時刻の順番を維持する。
総期間に到達した時点で止める。frameや累積イベント数は安全な整数範囲で扱い、32ビットへ切り詰めない。
メーターのtotal/applied/pendingは繰り返しを含む累積数とし、保存された配列長とは区別する。

即時制御の期限も最後のwriteから最大約49.7日とする。
音色エディターは定期的な2秒更新を廃止し、開始・有効な設定変更時だけI2Cを送る。
これにより長時間試聴でWorkerの累積音声命令予算を消費しない。

## 移行、停止と制約

プロジェクトのファイル・タブ・配線の形式は維持する。旧ドライバーは8秒検査を持つため、
サンプルを開く際に既知の同梱旧版と全文一致したライブラリだけ更新する。
旧版の正本は`src/drivers/pre-long-playback`へ保持する。開いた未編集タブも新しい内容へ同期し、
更新があった場合だけWorkerを再生成してimportキャッシュを破棄する。
編集済みファイル、未保存の変更、ルートやディレクトリによるmodule shadowingは引き続き拒否する。
準備はプロジェクトのコピーで行い、容量・競合失敗時は元のデータを維持する。

Pocket Signalは全64ステップ・960イベント・12.02秒とし、REPEAT_MSで24時間を指定できる。
初期値は1回で、不意の長時間演奏は開始しない。元の音色・時刻・FNUMを維持する。

手動停止、reset、再起動、例外、Worker障害、切断、背景移動、AudioContext中断で予約と出力を破棄する。
初期ミュート、出力リミッター、固定2 MiBの音源WASMメモリ、I2C転送量、イベント容量、
Worker送信予算と未受付メッセージ上限は維持する。
長時間のCPU使用は利用者が明示した演奏に従い、ページを前面で保ちOS・ブラウザが音声処理を
中断しない状態が必要。24時間の実時間連続運転や実チップ比較を検証済みとは扱わない。
異なる1,024件超の譜面を逐次供給する汎用ストリーミングや背景再生は対象外とする。

## 検証

I2Cのuint32高位ビット、24時間・最大値、旧命令互換、不正ループの原子的拒否、容量と転送失敗を検証する。
固定MicroPythonで長音・遅い開始・単旋律／複数トラックの24時間繰り返しを生成する。
サンプル時計を進め、24時間の終了境界と32ビットを超える絶対frameを44.1／48／96 kHzで検証する。
短い繰り返しと展開した譜面のPCM一致、周境界での同時刻順序、停止後の再発音防止を確認する。
全曲のレジスタ・960イベントと12.02秒のPCMを上流VGMと比較する。
ブラウザでは24時間予約の受付、2周目の実音声、追加送信がないこと、停止・復旧、旧版更新と
編集タブの同期・保護を検証する。24時間の実時間連続再生試験ではない。
