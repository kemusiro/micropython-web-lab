# ADR 0011: 実行資源の上限をWorker外から強制する

- 状態: Accepted
- 日付: 2026-08-28

## 背景

利用者のMicroPythonコードは無限ループや大量出力を行える。実行中のWebAssemblyはWorkerの
メッセージループへ制御を返さない場合があるため、Worker内へ停止要求やタイマーを送る方式では
応答不能なコードを確実に止められない。

手動の停止と⌘/Ctrl+CによるWorker再生成はM6.1で実装したが、不特定多数へ公開するには利用者の
操作がなくても可用性を回復する上限が必要である。

## 決定

`RuntimeClient`がメインスレッドで1回の実行を監視し、次の上限を適用する。

- スクリプト実行および改行を送ったREPL実行は10秒で打ち切る。
- 1回の実行で受信する標準出力と標準エラーの合計は100,000文字までとする。
- いずれかを超えたら、実行中のWorkerを`terminate()`し、新しいWorkerとWASMを自動生成する。
- 上限超過を制御エラーとしてUIへ通知し、REPLと仮想デバイス状態が初期化されることを示す。

REPLが主プロンプト`>>> `または継続入力プロンプト`... `を返した場合は、コード実行ではなく入力待ち
と判断してタイマーと出力カウンターを解除する。複数行コードの入力を考える時間は実行時間へ含めない。

端末画面は従来どおり古い表示を200,000文字で切り詰める。これはDOMとメモリの肥大化を抑える表示
上限であり、今回の1実行あたり出力量上限とは別に扱う。

## 結果

- 応答しないWASM自身の協力なしに、メイン画面から自動復旧できる。
- 上限を超えた実行ではREPL変数、仮想デバイス状態、実行中の補助検証状態が失われる。
- REPLで`input()`など独自の入力待ちを行った場合は通常プロンプトを検出できず、10秒で打ち切られる。
- ブラウザのメインスレッド自体を占有する脆弱性や、ページ再読み込みを繰り返す攻撃への完全な対策ではない。
- 制限値を将来変更する場合は、教育用作例の所要時間とサービスの可用性を一緒に評価する必要がある。
