# ADR 0044: I2C経由の連続試聴と音色変更の反映

- 状態: Experimental
- 日付: 2026-10-11
- 即時制御の期限延長と定期更新の廃止は[ADR 0046](0046-support-long-native-ym2203-playback.md)で更新。以下は当時の決定。

## 背景と選択肢

従来の音色エディターは1.5秒だけ試聴し、変更後は再度ボタンを押す必要があった。
利用者は音符を保持し、パラメーターを変更しながら音を確かめたい。
音源コアの8秒期限を解除する案、UIから直接発音する案、I2Cの即時制御で期限を更新する案を比較した。
既存のI2C経路と停止責務を保つ期限更新を採用する。スピーカー状態の日本語表示も
「ミュート中／ミュート解除」へ統一する。

## 決定

短い試聴を既定とし、「連続試聴」はモード選択後に「試聴する」を押したときだけ開始する。
開始時と設定変更時はモジュールをresetし、選択したFMまたはSSGの1chへ音色と音高を送り再発音する。
変更は80 ms待って最新の検証済み設定を送る。UIと独立したコントローラーが設定のコピー、
タイマー、実行環境の準備状態、停止後の自動再開防止を所有する。

発音中は2秒ごとに固定形式の短いPythonを実行し、I2C即時書き込みで8秒期限を更新する。
FMは既存のFNUM下位値、SSGは既存の音量・エンベロープ選択値だけを再送する。
キーオン、reset、エンベロープ形状の書き込みは更新に含めない。
更新前後のFM／SSG・ノイズ・エンベロープのPCM一致を固定音源コアで検証する。
連続試聴全体の時間上限は設けない。FMエンベロープの自然な減衰は設定どおりとし、
持続音のために利用者の音色設定を暗黙に変更しない。

自分の短いI2C処理中は次の送信を待つ。不正入力では発音を停止し、有効な修正後に再発音する。
不正入力が自身のI2C処理と競合した場合は、処理完了後に停止してWorkerを不用意に破棄しない。
明示停止、閉じる、Escape、外部の実行操作、実行環境の停止・再起動、背景タブへの移動、
切断、音声処理中断は継続の意図も破棄し、復旧しても自動再開しない。
ミュートは既存どおり出力だけを遮断し、試聴の音源処理と音量設定を維持する。

## 影響と移行

I2C命令、Runtime Protocol、Device SDK、Pythonライブラリ、保存形式、新規依存は変更しない。
MicroPythonへタイマーやブラウザAPIを公開せず、ユーザーコード・ファイルも上書きしない。
予約演奏は最大8秒、即時発音は最後の書き込みから8秒という制限を維持する。
更新が途絶えれば既存期限で消音する。音色エディターのPython書き出しは、選択モードに
かかわらず短いコード（FMは1.5秒の予約、SSGは1秒発音してreset）を生成する。
モードと試聴中の状態は永続保存しない。

## 検証

コントローラーの最新値反映、入力停止と復旧、実行待ち、停止後の遅延コール排除を単体検証する。
製品版Chromeで10秒を超えるSSGの実音声、期限更新でresetしないこと、音色・音高・チャンネル変更、
不正入力と修正、停止・閉じる・背景移動・再起動後の無音を確認する。
従来の短い試聴・Python書き出しとFM／SSGの演奏も再検証する。
