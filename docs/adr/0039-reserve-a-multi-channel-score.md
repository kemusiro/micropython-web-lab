# ADR 0039: FM＋SSGの複数トラックを一つの予約へまとめる

- 状態: Experimental
- 日付: 2026-10-11
- 予約時間と繰り返し指定は[ADR 0046](0046-support-long-native-ym2203-playback.md)で更新。以下は当時の決定。

## 背景と選択肢

従来の`reserve()`は単旋律用で、繰り返し呼ぶと前の予約を置き換える。
FM 3ch＋SSG 3chを同時に演奏するには、独立のplay命令で起点を合わせる方法と、
全トラックを一つの時系列にまとめる方法が考えられる。
別playでは現在の予約を置き換えてしまい、起点も配送の遅延に依存する。
既存のレジスタ予約を使って全トラックを一つのplayへまとめる方法を採用する。

## APIとスケジュール

追加ライブラリ`web_lab_ym2203_score_v1.py`は既存の`YM2203`を継承し、
`reserve_score(tracks, tail_ms=300)`を提供する。各トラックは音源、チャンネル、
MIDI音符／休符と、開始時刻・開始間隔・発音時間・SSG音量を持つ。
同じ音源の同じチャンネルを複数トラックに割り当てない。
最大6トラック、8秒、全体で1,024イベントに制限する。

全トラックと全音符を検査してからI2Cへ送る。選択したチャンネルには時刻0で停止命令を入れ、
開始が遅いトラックも旧音の継続を防ぐ。各イベントは時刻・停止/発音の優先度・明示的な順番を持つ。
キーオフは同時刻のキーオンより先に並べる。FM音程のhigh/lowレジスタの書き込みは
一組ずつ維持し、複数チャンネルの上位レジスタだけを先に並べない。
ソートの安定性や辞書の並び順には依存しない。

予約を最大63イベントずつI2Cへ送り、最後に一回だけplayする。
全トラックは同じAudioWorkletのサンプル時計を使う。
演奏期間は最も遅いトラックの終了時刻＋共通の余白。
選択外のチャンネルの発音状態は開始時に保持するが、終了時には従来どおりチップ全体を停止する。
転送失敗時には部分予約をresetで破棄する。停止・復旧のホスト責務は維持する。

## 配布と移行

既存の`web_lab_ym2203_v1.py`は変更しない。比較サンプルも維持する。
音源カードの別ボタン「合奏サンプル」で、追加ライブラリと新しいタブを用意する。
二つのライブラリをプロジェクトのコピーへ準備し、競合や容量超過ではどちらも追加しない。
編集済みのベース／追加ライブラリは自動上書きしない。
I2C契約v1、Runtime Protocol 15、Device API v1、保存形式は変更しない。
新規の本番依存や音声権限を追加しない。

## 検証

固定MicroPythonから実デバイスモデルへパケットを渡し、六つのチャンネルが実PCMへ寄与すること、
同時刻の停止・発音順、FM音程のレジスタ順、開始オフセット・休符、期間・容量、
転送の分割と失敗時の予約破棄を確認する。
ブラウザでは6chの混合演奏、Python終了後の継続、予約完了、保存・再読み込みと、
従来のFM/SSG比較・消音・停止・復旧を確認する。
