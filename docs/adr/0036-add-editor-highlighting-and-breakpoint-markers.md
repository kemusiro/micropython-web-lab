# ADR 0036: エディタの色分け・行番号とブレークポイントを表示する

## 状態

採用

## 背景

既存のtextareaにはインデント・保存・タブ切り替えがあるが、Pythonの構造や行番号、
デバッガが保持するブレークポイントを視覚的に確認できない。

## 決定

- textareaを入力とソースの正本として維持し、DOM依存の`CodeEditorView`で表示を分離する。
- 依存パッケージを追加せず、キーワード・文字列・コメントの字句による色分けを重ねる。
  文字列内部の式や構文の妥当性は解析しない。入力中の未完成コードも描画できる。
- 色分けは`textContent`で描画し、ソースをHTMLとして解釈しない。
- 行番号は空行と末尾の改行も含めて表示し、縦スクロールをtextareaへ合わせる。
  色分け表示は横スクロールも合わせ、同じフォント・行高・余白を使用する。
  1,000行を超える場合は行番号欄の表示範囲だけを描画し、大量の空行によるDOMの膨張を避ける。
- フォーカス中のカーソル行を強調し、停止行には黄色い矢印、ブレークポイントには赤い丸を表示する。
  同じ行の二つの印を独立して表示する。
- pdbの`break`／`clear`が実際の集合を変更した時点で、専用の`debugger-breakpoints`イベントを通知する。
  端末出力や入力コマンドから状態を推測しない。行番号は正の整数の昇順で、ソース容量上限に収まる。
- 内部Worker通信をv15へ更新し、現在の停止中の実行IDと一致する通知だけを受理する。
  UIとWorkerは同じ配布物で更新する必要がある。v14の通知は既存の版検査で拒否する。
- 再開時は停止行の印を消し、ブレークポイントは実行中も保持する。
  実行完了・エラー・Worker再生成ではブレークポイントも消去する。
- ブレークポイントの設定操作は既存のpdbコマンドを使用し、保存データ形式は変更しない。

## 結果

編集とデバッグの位置をエディタ内で確認できる。既存の保存・タブ・Tab操作を維持し、
外部エディタへの依存は追加しない。ブレークポイントはデバッグ実行ごとの状態で、永続化しない。
強制カラーモードではtextarea自身の文字色を使用する。
