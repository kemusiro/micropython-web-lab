# ADR 0049: I2C FM音源の実現性検証用音声経路

- 状態: Experimental
- 日付: 2026-10-11
- Pythonの時間上限は[ADR 0045](0045-disable-the-default-execution-deadline-for-alpha.md)、音源の予約時間上限は[ADR 0046](0046-support-long-native-ym2203-playback.md)で更新。以下は当時の決定。

## 背景と選択肢

YM2203のFM＋SSG音源を、I2Cで音色設定・予約演奏できる仮想モジュールとして検証する。
MicroPythonと同じWorkerでPCMを生成すると、同期Python実行中に音声生成用のJavaScriptタイマーが進行しない。
独立音声WorkerからPCMリングバッファを渡す方法は可能だが、追加バッファとWorkerのスケジューリングに依存する。

## 試作の決定

専用の`fm-prototype.html`で、固定コミットのymfmをWASM化しAudioWorkletへ配置する。
通常のDevice SDKと管理版の既定接続グラフには音声機能を追加しない。
公開Device API v1、接続・保存形式は維持する。Workerは専用ページの接続グラフに
`ym2203-prototype`がある場合にだけ、ホスト内部の音声sinkを持つI2Cモデルを登録する。

音声sinkはバージョン1の構造化命令だけを受け取り、Runtime Protocol 15の
`prototype-audio`イベントとしてメインスレッドへ送る。メインスレッドは検証済み命令を
AudioWorkletへ転送する。表示用`emitState`に音声命令やPCMを混在させない。
Workerの状態と発音側の内部状態は分離する。同期I2Cが成功しても音声処理が完了したことは保証せず、
レジスタ読み返し、BUSY、Timer A/B、IRQ、CSMの互換性は試作範囲に含めない。

予約は最大1,024イベント、8秒、単調な絶対ミリ秒オフセットを持ち、
AudioWorklet内で出力サンプル位置へ変換する。同時刻の命令順序は保持する。
予約再生の起点はAudioWorkletがplay命令を受け付けた位置であり、ホスト時計やPython時計との一致は保証しない。
即時命令の到着時間にはWorker・メインスレッド・MessagePortの遅延がある。
サンプルごとの通信を避け、将来の低遅延用途で必要になった時点で共有キューを検討する。

音源は4 MHz、ymfmのOPN_FIDELITY_MIN（内部約166.7 kHz）。出力レートへ面積平均で変換し、
FMとSSGをそれぞれ5 HzのDC除去フィルターへ通し、混合・音量制御・ピーク制限を行う。
出力段は混合PCMへ固定4倍とI2Cアンプ値（percent / 100）を適用する。
当初の固定0.25倍では、サンプルのアンプ35〜50%とホスト音量も重なり、最大スピーカー音量でも小さすぎた。
固定倍率を4へ変更し、通常音色は従来の16倍の振幅とする。FM／SSG間の比率やチップの音色レジスタは変えない。
全チャンネルの高出力設定では単純な増幅がクリップを招くため、瞬時アタック・50 msリリースの
ピーク包絡によるゲイン制限を行い、PCM振幅を0.95以内に収める。低出力時は線形に通す。
ホストのスピーカー音量（0〜1）と消音は制限後に適用する。停止時は包絡もクリアする。
I2C契約・保存形式・ドライバーの移行は不要。保存済みサンプルにも増幅が適用される。
これは試作用の再標本化であり、実DAC・アンプ特性、高品質帯域制限、ビット一致を保証しない。
音声処理のWASMメモリは固定2 MiB。WASIインポート、ネットワーク、DOMは持たない。

## 停止と上限

- Pythonは従来の10秒実行上限を維持する。予約演奏はPython完了後も継続する。
- 即時発音も最後の即時writeから最大8秒で止める。予約終了時にはチップと待機イベントをクリアする。
- 1 Workerにつき音声イベント1,024メッセージ／32,768数値の送信上限。到達時は診断可能な例外にする。
- メインスレッドからAudioWorkletへ未確認のメッセージは256件まで。
  10 Hzの音源メーター受信を配送進行の目安とする。厳密な命令ごとのACKではない。
- 停止・再起動・例外・Worker障害時、メインスレッドは音声停止を送り、独立GainNodeを0へ設定する。
  古いWorkerからの命令は既存RuntimeClientの世代検証で拒否する。
- バックグラウンド移行とページ離脱でPythonと音声を停止する。
- 任意PythonへAudioContext、MessagePort、PCM、共有メモリ、汎用JavaScriptを公開しない。
- HTTPS／localhostとAudioWorklet対応ブラウザが必要。初回クリックで音声を有効化する。
  初期化・読込・processor障害は表示し、音声を有効にし直せる。

## 移行と検証

通常版のUI・Device API・保存形式の移行は不要。Runtime Protocolは14から15へ更新し、
版不一致の拒否を維持する。Device SDKへ昇格する場合は、音声能力・状態同期・配線・
停止責務・タイマーステータスなどを別ADRで決める。

固定WASMのPCM、FM/SSG分離、音色差、予約のサンプル境界、容量検査を単体テストする。
ブラウザでI2Cからの発音、Python実行中と終了後の予約演奏、消音、停止、Worker復旧、
読込失敗を確認する。自動テストは音声グラフとPCMを検証するものであり、実スピーカーによる聴感評価を代替しない。
