# ADR 0009: REPL表示と入力状態を分離して端末内の直接入力を受け付ける

- 状態: Accepted
- 日付: 2026-08-26

## 背景

M6までのREPLはMicroPythonの出力を`pre`へ表示し、その下にある別の`textarea`へコードを入力して
送信する方式だった。複数行を確認してからまとめて実行する用途には適している一方、一般的なREPLの
ようにプロンプトへ続けて文字を入力したり、MicroPythonの入力履歴と行編集を利用したりできなかった。

表示要素自体を`contenteditable`にすると、ブラウザが管理するカーソルとMicroPythonが管理する
入力位置が別々になり、エコー、削除、履歴操作の状態がずれる。また、既存のWorker入力経路はすでに
文字列をUTF-8バイトへ変換し、`replProcessChar()`へ1バイトずつ渡している。

## 決定

REPL領域を、出力専用の`pre`と入力専用の不可視`textarea`で構成する。端末のクリックで入力要素へ
フォーカスし、入力確定文字列を既存の`input`メッセージでWorkerへ送る。IME変換中の未確定文字列は
送らず、`compositionend`後に送る。

Enter、編集キー、履歴キー、主要なCtrlキーはDOMイベントからREPL用シーケンスへ変換する。この変換は
DOMやWorkerへ依存しない関数として単体テストする。ブラウザ側は入力を端末へ描画せず、MicroPythonが
標準出力へ返すエコーだけを表示する。

MicroPythonが行編集時に返すBackspaceとANSI CSIシーケンスは、DOMから独立した端末画面モデルで
解釈する。表示文字列とカーソル位置を分けて保持し、行末消去や左右移動を反映してからDOMへ描画する。

複数行を確認してから一括送信する既存の入力欄と、保存可能なコードエディタは残す。直接入力は
ランタイムが`ready`の間だけ有効にする。

Workerがユーザーコードの実行で応答できない場合は、Ctrl+Cの配送も行えない。REPLへ行終端を送って
から主プロンプトが戻るまで、またはスクリプト実行中に⌘/Ctrl+Cを受け取った場合は、メインスレッドで
キーを捕捉してWorkerを破棄し、自動再生成する。これは通常の`KeyboardInterrupt`とは区別し、画面に
REPL状態が初期化されることを表示する。通常プロンプトではCommand-Cをコピー操作として残し、
Control-CはMicroPythonへ制御文字として送る。

## 結果

- プロンプト上で通常文字、削除、カーソル移動、履歴、制御文字を対話的に入力できる。
- MicroPythonを入力状態の正本とし、ブラウザ側に別の行編集状態を持たない。
- 文字入力、IME、モバイルキーボードをブラウザ標準の入力要素で受け取れる。
- ANSI表示、画面内カーソル、選択範囲などを備えた完全な端末エミュレーターではない。
- 応答しないPythonコードのキー割り込みでもWorkerを破棄するため、REPL状態は失われる。
