# ADR 0045: アルファ版の既定実行時間を無制限にする

- 状態: Accepted (alpha policy)
- 日付: 2026-10-11
- 音源の独立した予約時間上限は、後続の[ADR 0046](0046-support-long-native-ym2203-playback.md)で更新。

## 背景と選択肢

ADR 0011は、不特定多数へ公開した際に無限ループ等を利用者操作なしで回復するため、
スクリプトとREPLを10秒で打ち切るホスト監視を導入した。10秒はチップやWASMの必須制限ではなく、
可用性のための運用値である。睡眠や入力待ちも実行中の経過時間として計測するため、
正常な長時間実行まで止めてしまう。

利用者はアルファ版の間、実行時間を無制限にしたい。既存のDedicated Workerの強制破棄・再生成は
実行中のWASMの協力を必要とせず、時間上限を外しても手動停止から復旧できる。
現状は静的配信・クライアント実行であり、共有サーバー上に利用者のPython処理を置かない。

固定値を延長する案、利用者向け時間設定UIを追加する案、ホスト監視を任意設定として既定で無効に
する案を比較した。利用者の希望どおり最後の案を採用し、既存の停止操作を維持する。

## 決定

`RuntimeClientOptions.executionLimitMs`は省略または`null`なら無制限とする。
正の整数1〜2,147,483,647 msならホストのタイマーを有効にする。不正な値は起動前に拒否する。
通常・デバッグ・REPL、通常ワークスペース・実現性検証ページで同じ既定値を使う。
アルファ版UIには「実行時間は無制限・出力100,000文字まで」と明示する。
URLや保存データ、MicroPython APIからこのホスト設定を変更する経路は追加しない。

任意設定で時間制限を有効にした場合は、デバッガ待機・保存完了待ちを除いた経過時間を累積し、
期限でWorkerを破棄・再生成する。古い応答排除、停止後のタイマー解除、設定を保った再起動を維持する。
期限が無効でも操作の所有権と出力量は追跡するため、実行の重複拒否や大量出力の自動復旧は変わらない。

## 脅威、影響と代替手段

無出力の無限ループやデバイスを頻繁に更新するコードは、利用者が止めるまでCPUや通知処理を
消費できる。自動的なCPU実行期間の封じ込めはアルファ版の既定では保証しない。
対策は「停止」、REPL内の⌘/Ctrl+C、Worker再生成、出力量100,000文字、Pythonヒープ、
プロジェクト容量、転送・状態サイズ等の既存上限、固定Device Modelのレビューとする。
時間上限の再導入はホスト設定で可能とし、公開段階の見直し事項へ残す。

任意JavaScript・DOM・ネットワークの許可リスト境界、実行場所、Worker Protocol、Device SDK、
WASM、保存形式、新規依存は変更しない。音源の1予約8秒・1024イベントの制限は別の資源契約であり維持する。
時間制限の解除は、音源の予約枠を延長したり、背景移動時の音声停止を無効にしたりしない。

## 移行と検証

旧画面を再読み込みすると10秒の自動停止がなくなる。既存のコード・配線・保存プロジェクトはそのまま使える。
終了しない処理は明示的に止め、停止ボタン使用後は再起動する。REPL内の⌘/Ctrl+Cは既存の再生成経路を使う。

既定の通常・デバッグ・REPLが時間だけでは終了しないこと、手動停止と再起動、任意設定した期限、
デバッガ待機と保存待ちの除外、無効値拒否、出力量による回復を単体検証する。
ブラウザでは実際に10秒を超える有限スクリプトが終了してPython状態を保つこと、
Ctrl+Dで実行した無限REPLを期限経過後も強制停止できること、大量出力からの自動回復と
応答しないWorker外に退避したファイルの復元を確認する。

2026-10-11の検証では、全単体テスト286項目（53ファイル）、型検査、通常・Sakura配信用ビルドが成功した。
最終配信用ビルドでChrome E2E15項目が成功し、11.5秒の有限スクリプトと状態保持、
11.5秒を超えた無限REPLの強制停止、4種の大量出力からの回復、ファイル退避・容量上限、
デバッグ操作、日本語・英語表示、連続試聴、楽曲予約の保存・復元と停止を確認した。
