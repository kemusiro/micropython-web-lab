# ADR 0037: 音源試作を選択接続する内蔵デバイスとして統合する

- 状態: Experimental
- 日付: 2026-10-11
- オーディオ有効化・ミュート操作は[ADR 0043](0043-couple-audio-to-connections-and-separate-speaker-mute.md)で更新。以下は当時の決定。

## 背景と選択肢

ADR 0036の専用ページでFM・SSGの音声生成とI2C予約演奏が成立した。
通常の開発画面でもコード・接続設定を保存しながら試せるようにする。

公開Device SDKへ音声能力を追加する案は、外部デバイスによる音声生成、複数音源の配送、
状態同期・権限制御まで契約化する必要がある。内蔵の実験用デバイスとして扱う案では、
単一音源のホスト内部経路を再利用し、通常の配線・エディタとの連携を先に検証できる。
今回は後者を選ぶ。

## 決定と責務

`ym2203-prototype`を管理デバイスの選択カタログへ追加する。
カタログと既定接続を分け、既存の10デバイスの既定配線は変えない。
接続を適用すると通常のDevice UIカードを表示し、音声操作と波形をホストが付加する。
Device UI宣言の状態とAudioWorkletの発音状態は別々に保持する。

Workerは接続グラフに音源があるときだけ、既存の上限付き音声sinkを持つモデルを生成する。
メインスレッドはモデルを実行せず、manifestで配線を検証する。
音声操作は`YmAudioPanel`が担当し、明示的なクリックでAudioContextを有効化する。
起動時のstop/gainは音声が無効でも扱えるが、write/playは診断を表示してWorkerを停止する。
音声有効化はコードを自動実行せず、再読み込み後は再び利用者の操作を必要とする。

配線変更・切断・停止・再起動・実行エラーではホストのGainNodeを0にし、予約を破棄する。
音源を接続したページがバックグラウンドへ移る場合もWorkerと音声を停止する。
Python正常終了後の予約演奏は継続する。上限、合成方式、互換性の制約はADR 0036を引き継ぐ。

## 影響と移行

ADR 0036の「専用ページのみ、管理カタログに含めない」という範囲を拡張する。
専用ページは実現性検証用に残す。公開Device API v1、Runtime Protocol 15、保存形式v1は維持する。
既存の保存済み配線に音源を自動追加しない。新規接続は既存形式で保存し、再読み込みで復元する。
音源を知らない旧版で新しい配線を開くと検証に失敗し、従来の診断と既定配線への復旧を使う。
旧版へ戻す場合は先に音源を切断して配線を保存する。

追加の本番依存は導入しない。通常画面にも音声ホストのJavaScriptが含まれるが、
WASM・AudioWorkletの読み込みと音声処理の開始は音声有効化時に行う。
複数音源、外部Device SDK向け音声API、実機チップとの音質一致はこの変更に含めない。

## 検証

既定配線を維持したカタログの解決を単体テストする。
ブラウザでは通常UIでの明示的な接続、I2C scan、FMとSSGの分離演奏、
正常終了後の予約継続、接続とコードの復元、消音・停止・再起動・例外・切断、
音声有効化を忘れた場合の診断を確認する。
