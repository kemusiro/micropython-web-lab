# ADR 0003: スクリプトをWorkerプロトコル経由で一括実行する

- 状態: Accepted
- 日付: 2026-08-25

## 背景

M0はREPLへ文字列を入力する経路だけを実装した。エディタ上の作例や将来の複数ファイルプロジェクトを
扱うには、コードエディタのソース全体を一回の実行単位として渡し、完了とPython例外をUIが
識別できる必要がある。

ソースをREPL入力へ変換すると、複合文の終端、エコーバック、対話モード固有の表示に依存する。
また、スクリプト実行をメインスレッドへ追加すると、M0で設けたWorker隔離と強制停止の境界を
失う。

## 決定

スクリプトはMicroPythonをロード済みのDedicated Web Workerへ、バージョン2の
`execute`メッセージで送信する。メッセージはリクエストIDとソースコードを持ち、Workerは
MicroPythonの`runPython`でソース全体を実行する。

標準出力と標準エラーは既存の`stdout`、`stderr`メッセージで返す。正常完了とPython例外は
同じリクエストIDを持つ`execution-result`で返す。Python例外の後はランタイムを利用可能な
状態へ戻し、プロトコル不正やランタイム起動失敗を表す`error`とは区別する。

一つのWorkerで同時に実行できるスクリプトは一つとする。実行中はスクリプトの再実行とREPL
入力を無効にする。応答しないスクリプトは協調的な中断に依存せず、Workerを破棄して復旧する。

## 結果

- エディタ上のコードをREPL固有の入力形式へ変換せず実行できる。
- UIはスクリプトの完了とPython例外を区別できる。
- M0のWorker隔離と強制復旧モデルを維持できる。
- REPLとスクリプトは同じMicroPythonインスタンスを共有するため、再起動までグローバル状態が
  残る。
- 実行中の出力にはリクエストIDを付けないため、M1では同時実行を許可しない。
- ファイルシステム、プロジェクト保存、仮想デバイスは別のマイルストーンで扱う。
