# ADR 0047: 競合する音源ライブラリをバックアップして更新する

- 状態: Accepted
- 日付: 2026-10-12

## 背景

既知の同梱旧版だけを全文一致で更新する仕組みは編集内容を保護するが、
識別できない過去版も競合として止める。一般的なエラー文だけでは対象ファイルを特定できず、
手動でドライバーを移す操作が必要だった。利用者から実際に競合エラーが報告された。
報告されたプロジェクトの中身は取得できておらず、その版・編集の有無は確定していない。

## 決定

既知旧版の自動更新と、競合時に何も書き換えない既定動作は維持する。
競合エラーに対象パスを含め、サンプルを開く操作で「バックアップして更新」を表示する。
この操作を選んだ場合のみ、必要なライブラリと、importを隠す同名ファイル・パッケージを
`ym2203-backups/<未使用の連番>/files/`へ移す。未保存のタブ内容は別の`drafts/`へ保存する。
保存済みデータと下書きの両方を残し、開いているタブのパスを保存先へ移す。
関係のないコードやデータは変更しない。操作後に最新のサンプルを新しいタブへ開き、
Worker再起動で古いimportキャッシュを破棄する。

更新は現在のプロジェクトのコピーへ準備し、必要な全ライブラリ・下書き・容量を検査した後に
まとめて反映する。容量・パス・タブ上限等で失敗した場合は元のファイルと下書きを維持する。
ボタンを押すまで変更せず、「閉じる」でも変更しない。保存形式と公開Python APIは変更しない。
バックアップも通常のプロジェクトファイルなので保存・ファイル一覧・ZIP出力の対象となる。
競合表示時は待機中のエディタ自動保存を取り消し、ファイルを書き換えず下書きだけを保存する。
案内を読む間に未保存編集が元ファイルを置き換え、バックアップ内容が変わる競合を避ける。

## 検証

異なる保存済みドライバー、未保存編集、同名のルートモジュール・パッケージ、バイナリ、
既存バックアップ番号との衝突、容量失敗を単体テストする。
ブラウザでは競合パスの表示、閉じる操作、保存データと下書きの別保存、最新APIによる演奏、
古いimportキャッシュの破棄、開いている下書きタブの再読み込み後の復元を検証する。
