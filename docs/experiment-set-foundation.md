# 実験セットの保存基盤

用途別の題材を、コード、ファイル、構成、条件、観察画面、解説から成る「実験セット」として
開けるようにする。最初の段階では、現行のプロジェクトを壊さず取り扱う境界を用意する。

## 実装した境界

- `src/project/project-state.ts`は、現行の`StoredProject`と`ProjectPersistence`を定義する。
  `snapshotStoredProject`で既存の上限、タブID、パス、選択タブ、ファイル構造を検証し、
  タブとファイルのバイト列を複製する。保存済みファイルと編集バッファは別々に保持する。
- `ProjectStore`の読込と保存は同じ検証を通す。既存レコードは`project`ストアの`current`キー、
  版1を維持する。DB接続はE1で共通の版2管理へ移した。
- `ProjectWorkspace`は`ProjectPersistence`を受け取れる。通常の画面は従来どおり
  `ProjectStore`を使用する。保存前にコピーを確定し、成功後だけ保存済み比較基準を更新する。
  保存待ちの間に呼出元がタブ配列やファイルバイトを変更しても、保存対象へ逆流しない。
- `src/experiments/legacy-project.ts`は、プロジェクトと適用中の`ConnectionGraphV1`を
  ボード型の実験としてまとめる純粋な変換を提供する。ストレージやWorkerには触れない。
  この値は移行処理への入力であり、新しい永続保存形式ではない。

通常の自動保存でも無題タブへ名前を付けず、編集バッファをファイルへ書き込まない。
Pythonが書いたバイナリ、空ディレクトリ、CRLF、ファイルがなくなったタブも保持する。
実行状態、REPL出力、音声予約など、プロジェクト形式にないフィールドは取り込まない。

配線は既存の構造検証と64 KiBの保存上限を使う。構造が正しい未知のボード・デバイス参照は
その版のまま保持する。実行可能かの能力検査は別の責務であり、変換は実行許可を意味しない。
壊れた配線や未知の配線スキーマは拒否し、既定配線に置き換えない。入力プロジェクトは変更しない。

## 検証

契約テストは`project-state.test.ts`、`workspace-persistence.test.ts`、
`experiments/legacy-project.test.ts`に置く。既存の保存・復元テストと合わせて、次を確認する。

- ファイルと空ディレクトリ、バイナリ、下書き、無題、選択タブ、配線の保持。
- コピー間での編集の分離と、未保存表示を維持した保存・再読込。
- 保存完了前のファイル差替えを避け、保存失敗時に元のファイルを保持。
- 保存中に呼出元がデータを変更した場合の分離、不正なタブや過大なデータの拒否。
- Pythonによるファイル更新を古い編集バッファで上書きしない。

## E1の保存と切替

`ExperimentStore`にセットID、競合検出用revision、複数セットの保存、旧形式からの移行を追加した。
元セット、新セット、選択IDを同じトランザクションで確定する。旧データを保持し、移行後の旧経路の
書込を拒否する。未知・破損レコードは自動で置換せず、読取専用の回収APIを持つ。

`ExperimentCoordinator`は候補の準備、入力ロック、保存待ち、停止、一括保存、反映、起動を管理する。
`ExperimentProjectPersistence`を既存の`ProjectWorkspace`へ渡すと、ファイルと下書きを区別したまま
新しい保存経路を使える。古いセット・世代の保存要求を拒否し、失敗後も編集内容を保持する。
終了時退避もセットIDとrevisionへ結び付け、容量超過時に切り詰めない。

E1では通常画面の移行を自動で有効にせず、独立したテスト用ページで新しい保存経路を検証する。
DB版2は既存画面も使い、移行前の`project/current`と接続設定は従来どおり扱う。
仕様、上限、旧配布版への影響は[ADR 0051](adr/0051-add-transactional-experiment-set-storage.md)を参照する。

```sh
./scripts/use-node.sh pnpm test:e2e:experiments
```

## 次の段階

E2では右ペインの用途別の入口とボタン・LEDの題材を追加する。カテゴリを閲覧する操作と
実験セットを開く操作を分け、開く前に準備するコードと構成を示す。
その後にDOM非依存の物理モデル、MicroPythonとの同期実行の実証、アームとグラフの表示へ進む。

E2で現行画面の保存・配線・終了時退避を同時に新しい経路へ接続し、利用者の旧データを移行する。
Worker通信、Device API、本番依存パッケージはE1では変更しない。
